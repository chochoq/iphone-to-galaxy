# 2026-09-07 라이선스 선택과 배포 고지 검증

## 선택 전 질문

다른 사람이 이 프로젝트를 상업적으로 사용하는 것 자체를 막을지, 상업 배포는 허용하되 수정한
결과를 다시 공개하게 할지를 나눠 봤습니다. 비상업 조건은 판매를 막을 수 있지만 일반적인
오픈소스의 범위에서 벗어납니다. Apache-2.0과 CC BY는 오픈소스·오픈 콘텐츠이지만 수정본을 같은
조건으로 공개할 의무가 없습니다.

소유자는 두 번째 방향을 골랐습니다. 따라서 직접 만든 코드에는 GPL-3.0-or-later, 직접 쓴 문서에는
CC BY-SA 4.0을 적용합니다. 상업 이용은 가능하지만 배포된 수정본의 자유가 이어지는 조합입니다.

## 예상

1. 루트 `LICENSE`의 원문이 공식 GPL v3 전문과 일치합니다.
2. 문서, 외부 AirPods 렌더와 HiddenApiBypass의 조건을 파일별 안내에서 구분할 수 있습니다.
3. README·설계·태스크·공개 계획에 아직 라이선스를 정하지 않았다는 현재형 설명이 남지 않습니다.
4. AirPods Glance를 만들면 저작자 고지, CC BY 4.0 전문과 Apache 2.0 전문이 APK 안에 들어갑니다.
5. 라이선스 파일을 추가해도 개인정보·금지 파일 검사, 로컬 링크와 세 앱의 빌드는 그대로 통과합니다.

## 실행과 관찰

공식 배포처에서 받은 네 전문과 저장소 파일의 SHA-256을 비교했습니다.

- GPL-3.0: `3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`
- CC BY-SA 4.0: `28a9529c7d0bb4dc51f4bf5c116a3d16ef247a052f7591466768ddf563fd1cf5`
- CC BY 4.0: `9ba9550ad48438d0836ddab3da480b3b69ffa0aac7b7878b5a0039e7ab429411`
- Apache 2.0: `cfc7749b96f63bd31c3c42b5c471bf756814053e847c10f3eb003417bc523d30`

네 값이 모두 일치했습니다. `git diff --check`, Markdown 로컬 링크, 셸 문법과 공개 파일 검사도
통과했습니다.

Tap to Top, Holiday Sleep과 AirPods Glance를 다시 빌드했습니다. AirPods 핵심 검사 262,649개와
APK 권한 정책이 통과했습니다. APK에는 다음 세 파일이 들어 있었습니다.

- `res/raw/third_party_notices.txt`
- `res/raw/cc_by_4_0_license.txt`
- `res/raw/apache_license_2_0.txt`

세 파일을 APK에서 직접 꺼내 저장소 원문과 바이트 단위로 비교한 결과 모두 일치했습니다.
`check-public-tree.sh`는 공식 전문의 해시와 APK용 복사본을 검사하고, `verify-apk.sh`는 만들어진
APK 내부의 세 파일을 다시 검사하도록 고쳤습니다.

비공개 GitHub가 대표 라이선스를 어떻게 인식하는지는 push 뒤 확인합니다.

## 피드백 분석

예상한 로컬 결과와 실제 결과는 일치했습니다. 처음에는 저장소에 전문과 링크만 추가하려 했지만,
그러면 미래의 APK가 고지를 빠뜨려도 자동 검사가 잡지 못합니다. 그래서 제3자 전문의 APK 포함과
바이트 비교를 빌드·검증 계약으로 올렸습니다.

라이선스를 정한 뒤에도 저장소는 비공개입니다. 이 검증은 공개할 수 있는 권리 구조를 마련한 것이며,
실제 공개 전환이나 APK 배포까지 허락한 것으로 확대하지 않습니다.
