# APK 배포와 업데이트

유지관리자를 위한 배포 절차입니다. 앱 설치 방법은 [설치 안내](INSTALL.md)에 있습니다.
소스 커밋과 APK 배포는 별개이며, 배포할 변경을 모아 Release로 제공합니다.

## 서명 키

각 앱은 고정된 배포용 키로 서명합니다. 키와 비밀번호는 저장소·APK·Release·빌드 로그에 넣지 않습니다.
키를 잃으면 같은 서명으로 업데이트할 수 없으므로 안전한 별도 백업이 필요합니다.
키 교체가 필요하면 Android의 서명 계승과 OS 호환성을 검토하고 이관 방법을 안내합니다.

`build.sh`의 테스트용 키는 공식 배포용 키가 아닙니다.
서명 불일치를 해결하려고 사용자에게 곧바로 앱을 삭제하도록 안내하지 않습니다. 삭제하면 설정과 데이터가 사라질 수 있습니다.

## 1. 소스 고정

앱별 versionCode를 이전 배포보다 올리고 버전 이름을 정합니다.
관련 모델·UI 검사와 `sh tools/check-public-tree.sh`를 실행하고 배포 커밋을 고정합니다.
해당 커밋의 깨끗한 소스에서 빌드하며 SHA를 기록합니다. 개인 작업 폴더 전체를 압축하지 않습니다.

## 2. 빌드와 서명

JDK 17, SDK Platform 36, Build Tools 36.0.0을 준비하고 앱의 `build.sh`를 실행합니다.
`APK_RELEASE_KEYSTORE`, `APK_RELEASE_ALIAS`, `APK_RELEASE_PASSWORD`를 안전한 로컬 환경에 설정한 뒤 실행합니다.

~~~sh
sh tools/sign-release.sh tap-to-top /output/tap-to-top-VERSION.apk
~~~

앱 이름은 `tap-to-top`, `holiday-sleep`, `airpods-glance` 중 하나입니다.
출력 디렉터리는 미리 준비합니다. 이 도구는 키 생성·업로드를 하지 않으며 같은 출력 파일이 있으면 중단합니다.
비밀번호를 셸 기록이나 명령 인수에 직접 쓰지 않습니다.

## 3. 후보 검사

- 공식 인증서와의 일치, 최소 Android 버전, debuggable 해제, 권한·라이선스 포함 여부
- 새 설치·첫 실행·동일 APK 재설치
- 이전 공식 버전에서 삭제 없이 업데이트하고 시험용 설정 유지
- 해당 변경의 실제 기기 동작과 아직 확인하지 못한 범위

같은 APK 재설치와 버전 업데이트는 다른 시험입니다. 앱 데이터를 지워서 통과시키지 않습니다.
AirPods는 설치 조건과 AAP 경로의 OS 조건이 다릅니다. [설치 안내](INSTALL.md)를 함께 갱신합니다.

## 4. Release와 사후 확인

검증한 APK 세 개, 해당 커밋의 대응 소스, SHA-256 목록과 공개용 빌드 manifest를 첨부합니다.
대응 소스에는 GPL 소스·빌드 스크립트·제3자 고지를 포함합니다.
공개 인증서 지문과 APK 해시는 manifest에 기록하되 키·개인 설정·연구 로그·개인 화면은 제외합니다.

버전의 변화는 [변경 기록](../CHANGELOG.md)에, 확인 범위는 [호환성 안내](../compatibility/README.md)에 적습니다.
업로드한 파일을 다시 내려받아 해시·파일 목록·다운로드 링크를 확인합니다.

## 남은 검증과 외부 배포 정책

여러 Galaxy에서 다운로드부터 설치·권한·삭제까지 따라 하는 시험과 별도 환경의 키 백업 복구 시험은 남아 있습니다.
가상 기기에서 업데이트가 됐다는 결과만으로 모든 Galaxy의 설정·위젯·백그라운드 상태 보존을 보장하지 않습니다.

[Android 개발자 확인 안내](https://developer.android.com/developer-verification)의 지역별 적용과 설치 제한은
배포 시점에 다시 확인합니다. GitHub APK 제공이 개발자 확인이나 Play 심사 완료를 뜻하지는 않습니다.
