> 2026-09-10 갱신: 아래 첫 공개 계획은 당시 기록으로 보존합니다.
> 이제 소유자가 APK 배포를 요청해 `v0.1.0-preview.1` 미리보기를 제공합니다.
> 설치 파일은 Release에 첨부하며 서명 키는 계속 비공개입니다.
> 여러 Galaxy에서의 설치 시험은 남아 있습니다. 현재 절차는 [APK 배포](RELEASING.md)를 따릅니다.

## 저장소를 어떻게 소개할까

저장소 이름은 iphone-to-galaxy로 정했습니다. 첫 소개 문장은 README의 실제 경험에서 가져옵니다.

> 아이폰 3GS부터 아이폰만 사용하다 Galaxy Z Fold8으로 옮긴 사용자가, 손에 밴 사용법을 하나씩
> 다시 만든 기록입니다.

Apple 화면을 그대로 복제하거나 Galaxy를 아이폰처럼 꾸미는 앱 모음으로 소개하지 않습니다.
사람들은 앱 이름보다 ‘상태 표시줄을 눌러 맨 위로 가고 싶다’, ‘공휴일에는 수면 모드를 늦게
끝내고 싶다’처럼 자신이 겪은 문제로 들어오게 됩니다.

## 첫 공개에 넣을 내용

- 문제별 해결 과정과 설정 순서
- iPhone 14 Pro와 iOS 26.6.1이라는 경험의 기준
- Galaxy Z Fold8 SM-F971N, Android 17과 One UI 9.0에서 확인했다는 범위
- 맨 위로 톡, Holiday Sleep과 AirPods Glance의 빌드 가능한 소스
- 세 앱의 설계, 작업 내역, 실패와 기기 시험 결과
- 수면·회의·귀가·외출 루틴, 한손 제스처와 재난문자 설정
- 필요한 권한, 저장하는 정보, 삭제 방법과 호환성 제보 양식
- 자동 검사 설정

다음 자료는 넣지 않습니다.

- 설치용 APK와 배포용 서명 키
- 비공개 room, 원본 대화와 기기 로그
- 집과 회사 위치, Wi-Fi 이름, Bluetooth 주소, 개인 제품명과 계정
- Apple 공식 이미지와 촬영 영상, 다른 앱의 APK와 디자인 자료
- 설정 과정에서만 사용한 임시 입력 도구 routine-input-helper

마지막 도구는 사용자가 계속 쓸 제품이 아니라 설정을 돕기 위해 잠시 만든 도구입니다. 공개할 앱
수를 늘리려고 포함하지 않습니다.

## 공개 순서

2026-09-07 소유자의 요청으로 저장소를 공개했습니다. 공개 직전 기존 커밋의 CI 성공과 개인정보·
라이선스 검사를 확인했고, 공개 직후 비공개 취약점 신고 기능을 활성화했습니다.
아래 순서는 9월 7일 준비 당시 계획입니다. 당시에는 태그·APK 배포와 첫 Issue 작성을 하지 않았습니다.

1. ~~코드와 문서의 라이선스를 결정합니다.~~ `GPL-3.0-or-later`와 `CC-BY-SA-4.0`으로
   결정했습니다.
2. ~~실제 라이선스 전문과 필요한 제3자 고지를 넣습니다.~~ 파일별 범위와 세 라이선스 전문,
   APK 안의 고지를 추가했습니다.
3. 비공개 취약점 신고 기능을 켭니다. 공개 전에는 활성화하지 못했고, 공개 직후 활성화했습니다.
4. 마지막 개인정보 검사와 깨끗한 환경의 자동 검사를 통과시킵니다.
5. 저장소 설명, 주제 태그와 미리보기 이미지를 설정합니다.
6. 소유자가 명시적으로 확인하면 저장소를 공개로 전환합니다. 2026-09-07 완료했습니다.
7. `v0.1.0-source-preview` 태그를 만듭니다. 아직 APK는 첨부하지 않습니다.
8. 다른 Galaxy에서 결과를 알려 달라는 첫 Issue를 엽니다.

권장 주제 태그는 android, samsung, galaxy, one-ui, iphone-migration, good-lock, accessibility,
airpods와 open-source입니다.

## Issue를 나누는 방법

문제의 종류와 확인 상태를 하나의 이름에 섞지 않습니다.

- 종류: habit, recipe, app, bug, security, documentation, compatibility
- 사용한 방법: native, good-lock, third-party, adb-automation, custom-app
- 확인 상태: reproduced, implemented, device-verified, multi-device-verified, experimental
- 화면과 환경: fold-cover, fold-main, bar-phone, one-ui-9

첫 번째 목표는 새 앱을 더 만드는 일이 아닙니다. Fold8 이외의 Galaxy 두 대 이상에서 맨 위로 톡,
Holiday Sleep과 AirPods Glance가 어떻게 동작하는지 성공과 실패를 모두 받는 것입니다.

## APK를 배포하기 전에

소스를 공개한 뒤에도 APK는 바로 배포하지 않습니다. 다음 항목이 준비되면 별도로 판단합니다.

1. 배포용 서명 키를 보관하고 복구하며 교체하는 방법
2. 설치 파일의 해시와 다시 만들 수 있는 배포 빌드
3. Galaxy 두 기기 이상에서 설치, 권한 허용과 삭제 확인
4. 접근성 권한과 AirPods 숨은 API에 관한 눈에 띄는 안내
5. 업데이트 방법과 이전 서명의 호환성
6. Android의 외부 배포 및 개발자 확인 정책

## 무엇을 성공으로 볼까

GitHub 스타 수보다 다음 반응을 먼저 봅니다.

1. 다른 기기에서 다시 따라 할 수 있는 결과
2. 실제 적용하고 원래대로 되돌리는 데도 성공했다는 보고
3. 여러 사람이 반복해서 제보하는 아이폰 사용 습관
4. 설정 문서만으로 해결된 문제와 직접 앱이 필요했던 문제의 비율
5. 설치와 업데이트를 한 번에 해 달라는 요청

마지막 요청이 반복될 때에만 쉬운 설치 도구나 설정 안내 앱을 다음 제품으로 검토합니다.

처음 공개하는 글에는 완성된 앱만 나열하지 않습니다. 반복 스와이프가 왜 실패했는지, 수면 모드와
공휴일 규칙을 왜 나눴는지, AirPods 그림을 iOS와 다시 비교하고 무엇을 고쳤는지를 사례로 보여줍니다.

문서는 한국어를 먼저 쓰고 README에만 짧은 영어 소개를 둡니다. 다른 기기의 제보가 쌓이기 전에는
모든 설계 문서를 서둘러 번역하지 않습니다.
