# 세 앱의 공통 설정 화면

시간과 숫자를 편집할 때마다 다른 조작법을 익히지 않도록, 세 앱이 같은 화면 부품을 사용합니다.
앱별 `build.sh`가 이 폴더의 `src/`를 함께 컴파일합니다. 앱 폴더만 따로 복사하면 빌드되지 않습니다.

## 설계와 구현 순서

### 1.1.1 화면보다 값의 규칙을 먼저 분리

시간·숫자를 바꾸다 취소하면 이전 값이 남아야 합니다. 수면 시간의 시·분만 바꿨을 때 원래 초를
잃지 않아야 합니다. `EditorModel`에 입력 범위와 시간 계산을 두고 Android 화면 없이 검사합니다.
화면부터 고쳤다가 앱마다 취소·저장 규칙이 달라지는 일을 막기 위한 순서입니다.

### 1.1.2 저장 작업과 화면 수명 분리

저장 중 화면이 다시 만들어져도 같은 작업을 두 번 실행하지 않도록 `SaveJobs`에서 작업 ID를
관리합니다. `EditorDialog`는 초안과 원본을 구분하고 앱의 저장 어댑터에 결과를 맡깁니다.
실패했을 때 저장됐다고 알리거나, 기본값 복원 과정에서 권한까지 초기화하지 않습니다.

### 1.1.3 같은 조작은 같은 화면으로 연결

`SettingsPage`는 그룹형 설정 화면, `WheelColumn`은 시간 선택, `DetailsScreen`은 권한·진단
화면을 담당합니다. 앱은 저장 방식과 실제 권한 동작만 연결합니다. Android 시스템이 표시하는
권한 허용창은 이 UI로 대체하지 않습니다.

### 1.1.4 사진과 조작 결과로 간격 재검토

첫 구현 후 실제 화면에서 취소·저장 주변과 초기화 버튼 사이가 좁다는 피드백이 있었습니다.
공통 편집 화면의 여백을 고쳐 세 앱에 반영했습니다. 색상만 바꾼 것을 iOS와 같은 사용성이라고
주장하지 않습니다. 큰 글씨, 키보드, 취소, 저장 실패를 각각 검증 대상으로 둡니다.

## 다시 검사하기

저장소 루트에서 실행합니다. JDK 17이 필요합니다.

```sh
sh shared/android-ui/test-core.sh
sh apps/airpods-glance/test-core.sh
```

첫 명령은 입력 모델과 저장 작업을 검사합니다. 두 번째는 AirPods 핵심 로직과 위젯의 상태·크기
계산을 검사합니다. UI를 실제로 누르는 시험이나 Bluetooth 연결 시험은 아닙니다.

`tests/widget/`에는 별도 패키지 `com.chocho.widgettest`의 Android 검사 코드도 있습니다.
SDK Platform 36, Build Tools 36.0.0과 Node.js로 빌드할 수 있습니다.

```sh
node shared/android-ui/tools/build-widget-harness.mjs shared/android-ui/build/native-check
```

출력 폴더는 매번 새 경로를 지정합니다. 이 명령은 테스트 APK만 만들며 설치하지 않습니다.
실행은 별도 시험 기기에 해당 APK를 설치한 뒤 `com.chocho.widgettest.DensityChecks`
instrumentation을 사용합니다. 같은 패키지가 이미 있다면 덮어쓰지 않습니다.
검사에는 기기 권한이 필요 없으며 제품 앱의 저장소를 읽지 않습니다.

`DensityChecks`는 실제 Android 레이아웃을 생성·측정하고, `PreviewExport`는 예시 잔량으로
선택용 이미지를 만듭니다. 이것만으로 홈 런처의 탭 전달이나 재부팅 후 상태 유지를 확인할 수는 없습니다.

앱별 연결과 검사는 [기여 안내](../../CONTRIBUTING.md)에서 찾을 수 있습니다.
확인한 환경과 아직 시험하지 않은 동작은 [호환성 안내](../../compatibility/README.md)에 구분합니다.
