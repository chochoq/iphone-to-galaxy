# 상태 표시줄을 눌러 맨 위로 이동하기

## 아이폰에서는 어땠나

iPhone 14 Pro와 iOS 26.6.1에서는 화면 위쪽의 상태 표시줄을 누르면 보고 있던 내용이 맨 위로
올라갑니다. 갑자기 처음으로 점프하지 않고 한 번의 움직임으로 미끄러지듯 올라가며, 중간에 화면을
만지면 바로 멈출 수 있습니다.

One UI 9.0에는 모든 앱에서 통하는 같은 기능이 없습니다. Android 접근성에는 지원하는 목록에
목적지를 요청하는 경로가 있지만 모든 앱이 제공하지는 않습니다. X, YouTube, Chrome처럼
화면 구조와 지원 정보도 달랐습니다.

## 직접 해본 방법

GitHub에는 같은 목적으로 만든
[twelvehouse/TapToTop](https://github.com/twelvehouse/TapToTop)이 있습니다. 화면 위에 투명한
터치 영역을 두고 위쪽 스와이프를 여러 번 반복하는 앱입니다. 2026년 9월 7일 조사에서는 라이선스를 확인하지 못해
코드는 사용하지 않았습니다.

우리도 여러 방법을 시험했습니다.

- 스크롤 위치를 0으로 보내는 접근성 명령은 일부 Samsung 화면에서 애니메이션 없이 갑자기 이동했습니다.
- X의 홈 탭을 대신 누르는 방법은 보이지 않는 버튼의 좌표가 게시물과 겹쳐 엉뚱한 항목을 열었습니다.
- 짧은 스와이프를 여러 번 보내면 속도가 다시 빨라지는 모습이 반복됐고, 사용자가 중간에 화면을 내려도 계속 위로 올라갔습니다.
- 위쪽 플릭을 한 번만 보내면 아주 긴 피드의 처음까지는 못 갈 수 있지만 움직임이 자연스럽고 언제든 손으로 멈출 수 있었습니다.

초기 버전은 사용자가 움직임을 다시 잡을 수 있도록 한 번의 플릭을 선택했습니다.
이후 긴 피드에서 멈추는 한계를 다시 확인하고, 0.0.5에서 목적지를 요청하는 경로를 추가했습니다.

## 현재 동작

[맨 위로 톡](../apps/tap-to-top/)은 상태 표시줄을 누르는 동작과 아래로 끌어 알림창을 여는 동작을
구분합니다. 짧게 누르면 현재 화면의 지원 기능과 목록 방향을 확인해 맨 위 이동을 요청합니다.
지원하지 않으면 한 번의 플릭으로 돌아갑니다. 다음 플릭을 반복 예약하지 않습니다.

인스타·YouTube 홈은 실제 목록과 상단 영역을 찾아 상단 도착·중간 중단을 확인했습니다.
X 추천·팔로우 중 홈은 좌표가 아닌 선택된 홈의 의미 동작을 요청합니다. 준비 중 후속 동작은
취소할 수 있지만, X 자체 이동 중 원하는 위치에서 멈추기는 아직 확인하지 못했습니다.

## 접근성 권한

화면에서 스크롤할 수 있는 영역을 찾으려면 BIND_ACCESSIBILITY_SERVICE 권한이 필요합니다.
다른 앱의 화면 구조를 볼 수 있는 강한 권한이므로 소스를 검토하고 앱을 신뢰할 수 있을 때만
켜야 합니다.

인터넷, 사진, 마이크와 위치 권한은 요청하지 않습니다. 화면 내용이나 사용 기록도 저장하거나
전송하지 않습니다.

## 한계

- 웹·그리드·행 정보가 부족한 화면에서는 한 번에 맨 위 도착을 보장하지 않습니다.
- X의 이동 방식은 다른 목록과 다르며, 홈 재선택 때 새 글이 반영될 가능성이 있습니다.
- 앱이 제공하는 속도와 중단 동작을 iPhone과 똑같이 바꾸지는 않습니다.
- 아래로 쓸어 알림창을 여는 동작은 남겨 두었지만, 다른 기기에서는 터치 영역을 다시 확인해야 합니다.

기능을 끄려면 설정의 접근성 설치 앱에서 ‘맨 위로 톡’을 끕니다. 앱까지 삭제하면 상태 표시줄은
원래 One UI 동작으로 돌아갑니다.

Galaxy Z Fold8 SM-F971N, Android 17, One UI 9.0에서 X, YouTube, Chrome과 Samsung 설정을
시험했습니다.

커버 화면과 펼친 화면을 나눈 전체 회귀 검사는 아직 하지 않았습니다. 자세한 시험 내용은
[개발 안내](../apps/tap-to-top/docs/DEVELOPMENT.md)에 있습니다.
