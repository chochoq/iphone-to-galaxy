# 상태 표시줄을 탭해 맨 위로 이동하기

## 1. iPhone에서 익숙했던 경험

iPhone 14 Pro / iOS 26.6.1에서 화면 상단 상태 표시줄을 탭하면 현재 앱의 스크롤 영역이 위로
움직인다. 사용자는 한 번의 연속된 감속으로 느끼며, 이동 도중 화면을 만져 가로챌 수 있다.

## 2. Galaxy에서 관측한 차이

One UI 9.0에는 모든 앱에 공통인 이 동작이 없다. Android 접근성 API에도 타사 앱을 연속
애니메이션으로 절대 0 위치까지 보내는 공통 명령이 없다. 앱별 스크롤 구조도 달랐다.

## 3. 검토한 해결책과 반례

- `ACTION_SCROLL_TO_POSITION(0)`: 일부 Samsung 화면에서는 맨 위지만 중간 프레임 없이 점프했다.
- X의 홈 탭을 대신 누르기: 보이지 않는 노드 좌표가 아래 게시물과 겹쳐 엉뚱한 항목을 여는 반례가
  있어 기각했다.
- 여러 합성 플릭 반복: 빠름-느림-재가속이 생기고 사용자가 중간에 내리려 해도 입력을 빼앗았다.
- 한 번의 플릭: 아주 긴 피드의 절대 처음은 보장하지 못하지만 자연스럽고 즉시 가로챌 수 있었다.

## 4. 선택한 해결책

[`apps/tap-to-top`](../apps/tap-to-top/)의 접근성 서비스가 상태 표시줄 위의 탭과 아래 방향 드래그를
구분한다. 탭이면 현재 스크롤 후보에 의미 기반 위쪽 동작을 한 번 요청하거나 안전한 단일 플릭을
보낸다. X에는 조금 더 강한 한 번의 플릭을 쓰며 반복 예약은 하지 않는다.

## 5. 권한과 데이터

`BIND_ACCESSIBILITY_SERVICE`가 필요하며 화면의 접근성 노드를 볼 수 있는 강한 권한이다. 앱은
인터넷·사진·마이크·위치 권한이 없고 화면 내용과 사용 기록을 저장하지 않는다. 그래도 소스를
검토하거나 이 권한을 신뢰할 수 있을 때만 켜야 한다.

## 6. 알려진 부작용과 한계

- 긴 X 피드는 한 번에 완전한 처음까지 가지 않을 수 있어 다시 탭해야 한다.
- X, YouTube, Chrome과 앱 내부 WebView는 스크롤 노드 노출 방식에 따라 거리가 다르다.
- 상태 표시줄을 아래로 쓸어 알림창을 여는 동작은 보존하지만 기기별 터치 영역은 다시 확인해야 한다.

## 7. 원상복구

설정의 접근성 설치 앱에서 `맨 위로 톡` 서비스를 끈다. 완전히 제거하려면 앱을 삭제한다. 서비스가
꺼지면 상태 표시줄은 원래 One UI 동작만 한다.

## 8. 검증 범위

Galaxy Z Fold8 `SM-F971N`, Android 17, One UI 9.0에서 X·YouTube·Chrome과 Samsung 설정을
시험했다. 현재 공개 기록은 한 화면 구성의 단일 기기 결과이며 커버/펼친 화면 각각의 완전한 회귀
행렬은 아직 없다. 상세 관찰과 기각 이력은 [앱 설계 인덱스](../apps/tap-to-top/docs/design/INDEX.md)에
있다.
