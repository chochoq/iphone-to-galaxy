# 004 — 위젯·알림·앱 화면 경험

## 1. 홈 화면 위젯

### 구현 중 발견과 설계 반영 — 2026-09-04

Samsung One UI의 `requestPinAppWidget` 추가 창은 provider의 `initialLayout`만으로 실제
widget 등록은 가능하더라도, 등록 전 카드에는 별도의 `previewLayout`을 요구했다. 첫 실기기
시도에서 provider가 목록에 등록된 상태인데도 미리보기 영역이 `위젯을 추가할 수 없습니다`로
대체되는 것을 UI dump와 `AppWidgetHostView: missing defaultLayout` 로그로 확인했다.
따라서 실제 레이아웃과 같은 안전한 정적 레이아웃을 `previewLayout`으로 명시하고, 추가 전
미리보기와 추가 후 `RemoteViews`를 서로 따로 검증한다. 이 발견은 배터리 데이터 흐름을
바꾸지 않지만 “picker에 노출됨”만으로 위젯 UX가 완료됐다고 판단하면 안 된다는 검증 조건을
추가한다.

### 기본 크기

- 기본 4×1, 최소 2×1까지 축소 가능하게 설계
- Fold 외부 화면 1248×1972 기준에서도 한 줄 숫자가 잘리지 않아야 함
- 테마 배경색을 사용하고 과도한 AirPods 복제 애니메이션은 넣지 않음

### 4×1 정보 계층

```text
에어팟 한눈에                         ↻
왼쪽 80% ⚡     오른쪽 70%      케이스 40%
연결됨 · 방금 확인
```

### 축소 상태

```text
L 80  R 70  C 40
연결됨 · 방금
```

### 상태 표현

- `—`: 이번 관측에서 값을 알 수 없음
- `⚡`: 현재 연결 + 최근 관측에서 충전 중
- `마지막 확인 2시간 전`: 캐시이며 현재값이 아님
- `배터리 확인 중`: 연결은 확인했지만 유효 packet 없음
- `기기 확인 필요`: 주변 packet은 있으나 선택 기기 identity가 확정되지 않음

새로고침 버튼은 값을 즉시 만들어 내겠다는 약속이 아니다. 연결 중이면 scan을 재시작하고,
미연결이면 앱을 열어 이유를 보여 준다.

## 2. 연결 팝업

초기판은 시스템 알림을 사용했다. 2026-09-04 실사용에서 사용자가 “그냥 알림처럼 작다”고
피드백했고, MaterialPods에서 유용했던 큰 연결 카드 크기를 광고 없이 원했다. ADR-009의
재개방 조건이 충족됐으므로, 선택 권한 기반의 짧은 application overlay를 주 표면으로 바꾼다.

**후속 정정:** 아래의 남색 상단 카드 레이아웃은 첫 기능 검증 당시의 역사다. 실제 동작은
통과했지만 사용자의 두 번째 피드백에서 Apple 화면과 너무 다르다는 점이 확인됐다. 현재 시각
source of truth는 [007 — Apple 실제 화면 기반 연결 시트](007-apple-like-connection-sheet.md)이며,
밝은 하단 시트·배경 dim·제품 중심 계층으로 교체됐다. 권한·잠금·fallback 계약은 유지하지만,
DND를 큰 카드 금지 조건으로 둔 판단은 2026-09-05 실기기 반증 뒤 설계 009에서 폐기됐다.

### 큰 카드 레이아웃

```text
┌────────────────────────────────────┐
│  [AirPods]  테스트용 AirPods Pro  × │
│             Galaxy에 연결됨          │
│                                    │
│    왼쪽          오른쪽       케이스   │
│     87%           94%          —      │
│                   충전 중              │
│          6초 후 자동으로 닫혀요         │
└────────────────────────────────────┘
```

- 현재 화면 너비에서 좌우 16dp 여백을 남기고 상단에 배치한다.
- 전체 화면을 가리지 않고 6초 뒤 자동 제거한다.
- 카드 전체를 누르면 앱을 열며, `×`는 즉시 닫는다.
- 값이 없는 component는 `0%` 대신 `—`, charging은 색만 아니라 글자로 표시한다.
- 첫 exact snapshot 뒤 연결 세션당 한 번만 표시한다.

### 표시 정책 반복 검증

1. **정상 사용:** overlay 권한 있음 + 화면 켜짐 + 잠금 해제 + 값 있음이면 DND 여부와 무관하게
   소리·진동 없는 큰 카드.
2. **수면/잠금:** 화면 꺼짐 또는 keyguard 잠김이면 큰 카드 없음. widget/ongoing 알림은 갱신.
3. **권한 거부:** 연결과 battery 수신은 계속되며 기존 high-importance 알림을 8초 fallback으로 표시.
4. **저전력 동시 발생:** low-battery 알림이 우선하며 연결 카드는 겹치지 않는다.
5. **반복 push:** session `popup_shown` claim 뒤에는 overlay와 fallback 알림 모두 다시 생성하지 않는다.
6. **수명 종료:** disconnect, Bluetooth off, service destroy에서 아직 보이는 view를 즉시 제거한다.

full-screen intent는 전화·알람 범위가 아니므로 사용하지 않는다. 투명 Activity는 Android의
background activity launch 제한 때문에 연결 broadcast에서 신뢰할 수 없다. 따라서 사용자가
특별 권한을 명시적으로 켠 경우에만 `TYPE_APPLICATION_OVERLAY`를 쓰고, 나머지는 알림으로
되돌아가는 구조가 이 시나리오에 가장 예측 가능하다.

기존 알림 fallback은 다음 계약을 유지한다.

- 첫 fresh snapshot 뒤 한 번
- 제목: 페어링 이름 또는 `AirPods 연결됨`
- 내용: `왼쪽 80% · 오른쪽 70% · 케이스 40%`
- charging component가 있으면 `충전 중`을 덧붙임
- 6~8초 뒤 자동 사라짐
- 눌렀을 때 앱의 상세 상태로 이동
- notification fallback은 DND, 잠금화면 알림 설정, 알림 권한을 시스템 정책대로 존중

연결 직후 값이 없으면 빈 팝업을 띄우지 않는다. foreground notification의 `확인 중`만
보이고, 값이 들어온 순간 connection popup을 낸다.

설계하면서 느낀 점은 크기가 곧 방해라는 단순한 관계는 아니라는 것이다. 사용자가 연결 순간
원한 것은 광고 앱의 체류가 아니라 정보를 놓치지 않을 정도의 시각적 확신이었다. 그래서
카드는 커지지만 시간은 짧아지고, 화면을 보고 있지 않은 때에는 더 조용해지는 방향이 맞다.

### 미리보기에서 발견한 시스템 inset 수정

Android 17 edge-to-edge 환경에서 기존 `MainActivity`의 첫 제목이 status bar 아래로 들어간 것이
큰 카드 screenshot에서 드러났다. overlay frame 자체는 system이 status bar 아래에 배치했지만
뒤 화면의 고정 22dp padding은 system bar 높이를 포함하지 않았다. root가 `systemBars()` inset을
받아 기존 여백에 더하도록 수정한다. 이는 큰 카드 위치를 바꾸지 않고 앱 화면의 제목과 하단
버튼이 system UI에 가려지지 않게 하는 구현 피드백 반영이다.

## 3. 연결 중 알림

- foreground service 요구를 숨기지 않고 실제 기능 상태로 사용
- 중요도 LOW, 소리·진동 없음
- 배터리가 바뀌면 텍스트만 갱신
- 연결 해제 시 즉시 제거
- `대기 중`, 광고, 구매, 평가 문구 없음

## 4. 배터리 부족 알림

- 기본 이어버드 20%, 케이스 15%
- unknown component는 판정하지 않음
- 20% 패킷이 여러 번 와도 한 번만 알림
- 30% 이상 회복 또는 새 연결 세션 뒤 다시 감시 가능
- 연결 팝업과 동시에 조건을 만족하면 알림 두 개를 겹치지 않고 부족 알림을 우선

## 5. 앱 메인 화면

### 상단

- 앱 이름과 선택 AirPods 이름
- 연결 상태 badge
- 마지막 확인 시각

### 배터리 카드

- 왼쪽, 오른쪽, 케이스 세 칸
- 큰 숫자와 charging 상태
- 공개 BLE가 10% 간격임을 작은 안내로 명시

### 설정·진단

- 자동 감시 사용 switch
- 연결 팝업 switch
- 연결 중 알림은 foreground 제약 때문에 감시 사용 시 필수라고 설명
- 낮은 배터리 알림 switch 및 기준값
- 권한 상태
- 페어링 기기 상태
- 마지막 scan 결과: 유효/ghost/주소 불일치/미수신 카운트
- Bluetooth 설정 열기

진단에는 원시 Bluetooth 주소와 packet bytes를 기본 표시하지 않는다. 필요한 경우에도
로컬 화면에 일시적으로만 보여 주고 공유 기능은 만들지 않는다.

## 6. 접근성

- 색만으로 charging과 연결 상태를 구분하지 않음
- `L/R/C`만 쓰는 축소 위젯을 제외하고 앱과 큰 위젯에는 `왼쪽/오른쪽/케이스` 사용
- 퍼센트와 상태를 content description에 함께 제공
- 시스템 글자 크기가 커져도 앱 화면은 세로 스크롤 가능
- 위젯은 숫자를 자르기보다 긴 장식 문구를 먼저 줄임
