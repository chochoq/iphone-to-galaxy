# 소음 제어 — 시나리오부터 실제 응답까지

2026-09-15. 노이즈 캔슬링·적응형·주변음 허용의 구현과 검증 기록입니다.
소스에는 포함됐지만 현재 다운로드 APK에는 아직 없습니다. 소음 제어 위젯은 이 변경에 포함하지 않습니다.

## 1. 설계 색인

1. 사용자 시나리오와 최선의 동작
2. 연결과 상태 계약
3. 의존성 순서에 따른 구현 과정
4. 아이콘·화면 자료의 수정 과정
5. 확인한 결과와 남은 범위

## 2. 사용자 시나리오와 최선의 동작

| 상황 | 최선의 동작 | 확인 방법 |
|---|---|---|
| 연결된 AirPods의 모드를 알고 싶다 | 앱을 열면 현재 상태를 읽고 기기 응답을 표시 | 실제 보고와 UI 비교 |
| 다른 모드를 누른다 | 한 번만 전송하고 응답 전까지 이전 실제 선택 유지 | 중복 입력·늦은 보고·모드 순서쌍 검사 |
| 배터리도 확인한다 | 제어와 연결을 공유하고 잔량의 원래 수신 시각 유지 | 늦은 소비자 합류·실기 갱신 |
| 연결이 끊기거나 앱을 나간다 | 대기 요청 폐기, 재연결 후 자동 재전송 없음 | 연결·화면 수명 경계 검사 |
| 응답이 없다 | 성공으로 꾸미지 않고 확인 실패 안내 | 타임아웃·이전 값 표시 검사 |
| 작은 화면이나 큰 글씨를 쓴다 | 세 모드 이름과 터치 영역을 유지 | 너비 네 가지 × 글씨 세 크기 × 상태 여덟 가지 |

시나리오는 세 번 검토했습니다. 첫 검토에서는 요청한 모드와 실제 모드를 분리했고, 두 번째에서는
배터리와 제어의 동시 연결을 하나로 합쳤습니다. 마지막에는 앱을 나가거나 기기가 바뀐 후 예전 요청이
다시 실행되지 않도록 화면의 수명과 요청을 묶었습니다.

## 3. 연결과 상태 계약

`ListeningProtocol`은 세 모드 명령만 허용합니다. 임의 패킷·끔 명령·자동 재시도는 없습니다.
`ListeningState`는 관측값, 요청값, 대기·종료 상태를 별도로 관리합니다.
`AapConnectionOwner`가 배터리와 제어 소비자의 연결 하나를 소유하고, 최대 30초 뒤 닫습니다.
응답 확인에는 5초를 확보하며, 연결 시간이 부족하면 그 창이 끝난 후 해당 탭에 한해 새로 확인합니다.

`ListeningController`는 Android 17 이상, 근처 기기 권한, 앱에서 선택한 페어링 대상과 실제 A2DP 연결을
확인합니다. 앱이 전면에 있을 때만 제어하며 화면 이탈·대상 변경·연결 종료 뒤 이전 명령을 재생하지 않습니다.
배터리만 읽는 소비자에는 모드 변경 권한이 없습니다. 새 권한·서버 통신·오디오 프로필 조작은 추가하지 않았습니다.

## 4. 의존성 순서에 따른 구현 과정

### 1.1.1 프로토콜과 요청 수명부터 고정

화면 버튼부터 만들면 전송과 성공 표시가 섞이기 쉽습니다. 먼저 프레임 길이·허용 모드·단조 시각·
이전 응답·중복 선택·타임아웃을 순수 모델로 검사했습니다. 응답에 요청 ID가 없으므로 특정 ACK라고
단정하지 않고, 한 번 전송한 뒤 같은 연결에서 목표 모드 보고를 받았는지 확인합니다.

### 1.1.2 공유 연결과 배터리의 원래 시각 보존

배터리 수신이 먼저 끝난 뒤 화면에서 늦게 참여한 소비자가 값을 놓치는 반례가 있었습니다.
같은 연결 안에서 유효한 최근 배터리 보고를 전달하되, 전달 시각을 새 측정 시각으로 바꾸지 않도록
수정했습니다. 연결 종료·대상 변경 때 저장된 보고도 폐기합니다.

### 1.1.3 두 모드 검증 후 적응형 추가

노캔·주변음의 실제 전환과 음악 재생을 먼저 확인했습니다. 적응형은 별도 진단에서 목표 보고를 받은 뒤
제품의 허용 목록에 추가했습니다. 이름만 보고 지원한다고 가정하거나 회색 버튼만 활성화한 것이 아닙니다.
적응형 강도·대화 인지·개인 맞춤형 음량 제어는 다른 기능으로 남겼습니다.

### 1.1.4 실제 View와 폰 화면 비교

그림·이름·상태·접근성 설명을 실제 제품 View로 검사합니다. UI 검사 앱에는 Bluetooth 권한과 controller가
없습니다. 다만 본앱 위에서 검사 Activity가 끝나면 본앱이 다시 전면으로 돌아와 읽기를 시작하는 반례가
있었습니다. 이후에는 홈에서 검사를 시작합니다. 시험 앱의 무권한 상태를 폰 전체의 무통신 상태로
오해하지 않도록 실행 절차를 정정했습니다.

## 5. 아이콘과 화면 자료

Apple 공식 iOS 26 화면과 비교해 사람+실선, 사람+점선, 사람+반짝임이라는 기호를 사용했습니다.
Canvas 도형은 직접 작성했고 Apple PNG나 SF Symbols 경로를 제품에 복사하지 않았습니다.

첫 렌더는 큰 크기에서 분리됐지만 26px에서 실선·점의 끝이 어깨와 붙었습니다. 그림의 양 끝을 올리고
26/68/156px 모두 머리·몸·장식의 분리를 검사하도록 고쳤습니다. 최종 렌더와 실제 폰 화면도 직접 확인했습니다.

README의 세 이미지는 이 제품 View를 Android에서 실행한 선택 상태 예시입니다. 개인정보는 넣지 않았으며
실제 명령 전송이나 소음 효과의 증거로 쓰지 않습니다. [화면 자료 출처](../../../../docs/images/#소음-제어--다음-업데이트).

## 6. 확인한 결과와 남은 범위

- Fold8·Android 17·One UI 9.0에서 본앱의 세 모드 전환과 기기 보고·UI 일치를 확인했습니다.
- 적응형 별도 진단은 전송 뒤 969ms, 제품 적응형↔노캔은 각각 839ms/1,021ms 뒤 목표 보고를 받았습니다.
- 연결·재생 표본을 관측했고 사용자는 전환 뒤 음악 끊김이나 튐이 없었다고 확인했습니다.
  표본 관측만으로 짧은 음질 변화나 환경별 적응 효과까지 입증하지는 않습니다.
- 순수 소음 제어 657개, 기존 core 263,039개, 잠금 위젯 7,388개 검사를 통과했습니다.
- 실제 Android View/아이콘 검사 3,415개와 문서용 상태 렌더 검사 72개를 통과했습니다.
- 개인 설치 시 기존 서명·설정·위젯 등록을 유지했고, 설치 파일과 빌드 후보 해시를 대조했습니다.

다른 Galaxy·AirPods 모델, 환경별 적응 강도, 장기 배터리 영향은 확인하지 않았습니다.
APK 배포와 위젯 제어는 별도 단계입니다. 원시 로그·개인 기기 정보·Apple 참조 이미지는 공개하지 않습니다.

재현: `sh test-listening.sh`, `sh test-core.sh`, `./build.sh`, `./verify-apk.sh`.
실제 View 검사와 이미지 출력은 [검사 앱 안내](../../tests/listening-ui/README.md)를 따릅니다.
