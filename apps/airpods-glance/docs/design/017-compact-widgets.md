# 017 — 작게 놓고 크게 읽는 원형 위젯

2026-09-14 · 소스 변경 기록. 다운로드용 APK에는 아직 반영하지 않았습니다.

## D17.1 사용자 시나리오

| 원하는 사용법 | 선택 | 남기는 정보 |
| --- | --- | --- |
| 세 부품을 여유 있게 한 번에 확인 | 3×1 | 왼쪽·오른쪽·케이스의 원과 잔량 |
| 홈 공간을 더 적게 사용 | 2×1 | 같은 세 부품, 줄인 가로 여백 |
| 한 칸만 사용 | 1×1 | 한 부품의 원·잔량·이름, 탭으로 순환 |

처음에는 2×2·4×1·4×2를 작다고 판단했지만 실제 홈에서 여전히 크다는 피드백이 있었습니다.
크기 선택지만 늘리는 대신 최종 기본값을 3×1·2×1·1×1로 좁혔습니다.
이전 큰 타입은 이미 놓인 위젯이 사라지지 않도록 유지하고 새 선택지에서는 숨깁니다.

## D17.2 의존성이 큰 부분부터 구현

### 1.1.1 상태와 관측값을 표시 정책에서 분리

`WidgetState`는 이미 수신한 잔량을 표시 정보로 바꿉니다. 그림을 그리려고 Bluetooth를 새로
연결하지 않습니다. 모르는 값은 ‘—’, 오래되거나 연결이 끊긴 값은 회색으로 보입니다.
다른 부품을 선택했다고 직전 부품의 숫자가 남으면 실패입니다.

### 1.1.2 실제 공간에서 원과 글씨 크기를 계산

`WidgetLayout`이 표시 방식을 고르고 `WidgetSizing`이 글씨 공간을 먼저 확보합니다.
남는 높이에서 원 크기를 계산하고, 이미지도 View에 맞게 확대합니다. View만 커지고 그림은
작게 남는 문제를 함께 고쳤습니다. 휴대폰 전체의 글씨 크기나 홈 격자는 바꾸지 않습니다.

한 줄 위젯에서는 긴 기기명과 상태 줄을 생략하고 원과 잔량을 우선합니다.
부품 이름과 확인 시각은 접근성 설명에 남깁니다. 큰 글씨로 공간이 부족하면 목록이나 앱 열기로
전환하며, 이때 탭 동작과 설명도 실제 동작에 맞춥니다.

### 1.1.3 1×1 선택을 위젯마다 기억

한 칸은 왼쪽 → 오른쪽 → 케이스 순으로 바뀌도록 구현했습니다. 선택값은 위젯 ID별로 저장하고,
갱신 시에는 선택을 읽기만 합니다. 실제로 등록된 한 칸 위젯인지 확인한 뒤 해당 위젯만 갱신합니다.
3×1·2×1을 누르면 앱이 열립니다. 잠금화면 시계 아래 위젯은 이번 구현에 포함하지 않습니다.

### 1.1.4 미리보기와 실제 런처를 별도로 확인

미리보기는 제품의 실제 렌더 코드로 생성합니다. 예시 화면이 예쁘다는 이유만으로 홈에서도
동작한다고 판단하지 않고, 삼성 추가창의 칸 수와 실제 홈의 원·숫자를 따로 확인합니다.
삼성 홈의 1×1 실측 폭은 약 122dp로 예상한 89dp와 달라 둘 다 검사 조합에 넣었습니다.
한 칸이 물리적으로 완전한 정사각형이라는 뜻은 아닙니다.

## D17.3 반복 검증과 남은 것

- 순수 상태·크기 검사와 실제 Android의 밝음/어두움·글씨 크기·잔량 상태별 레이아웃 검사.
- Fold8 커버 화면에서 삼성의 3×1·2×1·1×1 추가창 확인 및 실제 홈 표시 확인.
- 기존 위젯은 삭제하지 않고 크기만 줄여 확인. 1×1은 별도로 한 개 추가해 표시 확인.
- 1×1의 실제 홈 탭 전환, 재부팅 후 선택 유지, 다른 런처, 펼친 폴드와 TalkBack 음성 탐색은 미검증.

자동 검사에서의 이름·잔량 재적용 통과를 실제 홈 탭 전환 통과로 쓰지 않습니다.
새 배터리 수신, 음악 유지, 케이스 소리 재생도 이번 화면 검사의 결과가 아닙니다.
