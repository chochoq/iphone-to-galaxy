# 018 — 잠금화면 한 칸에서 부품 바꾸기

2026-09-14 · v0.0.3. [사용법](../../README.md#잠금화면에-넣기)

## D18.1 왜 만드는가

배터리를 보려고 잠금을 풀고 홈 화면까지 들어가야 하는 동선을 줄인다.
홈 위젯을 작게 복사하는 것이 아니라, 삼성 잠금화면 편집기의 시계 아래 공간에 맞춘다.
작은 공간에서는 제목·설명·새로고침보다 부품 구분과 숫자가 먼저다.

## D18.2 시나리오와 원하는 동작

| 상황 | 동작 | 피해야 할 결과 |
| --- | --- | --- |
| 빈칸이 하나다 | 한 칸을 추가하고 탭으로 세 부품을 본다 | 세 칸을 모두 넣어야 함 |
| 특정 부품부터 보고 싶다 | 선택 목록에서 시작 부품을 고른다 | 비슷한 이름의 세 위젯을 구분 못 함 |
| 두 칸을 넣었다 | 각 칸의 마지막 선택을 따로 기억한다 | 하나를 누르면 다른 칸도 바뀜 |
| 연결이 끊겼다 | 마지막 수신 잔량을 작은 시계와 함께 표시한다 | 현재 측정값처럼 보임 |
| 값이 없거나 잘못됐다 | ‘—’와 빈 원으로 표시한다 | 추측한 값이나 0%로 채움 |
| 잠긴 상태에서 누른다 | 표시 부품만 바꾼다 | 앱 실행, 소리, 잠금 해제나 Bluetooth 재연결 |
| 기존 위젯이 있다 | 배치를 보존한다 | 업데이트하면서 사용자의 배치를 바꿈 |

## D18.3 판단을 바꾼 과정

처음에는 왼쪽·오른쪽·케이스를 별도 위젯으로 만들고 부품 이름을 글자로 표시했다.
사용자는 글자보다 아이콘을 원했고, 홈 1×1처럼 한 칸에서 탭으로 바꾸는 방식을 요청했다.
이에 공급자 세 개는 기존 배치를 보존하기 위해 유지하되, 모두 같은 순환 동작을 하도록 바꿨다.
이제 세 항목의 차이는 처음 표시할 부품뿐이다.

‘현재 잔량’이라는 표현도 쓰지 않는다. 배터리 수신이 멈춰도 위젯 그림은 남을 수 있다.
연결 여부나 경과 시간에 따라 실시간처럼 보이게 하기보다 항상 마지막 수신 기록으로 취급한다.
충전 번개는 과거 상태를 현재로 오해하게 할 수 있어 넣지 않았다.

## D18.4 구조와 표시

- `LockWidgetState`: 저장된 배터리를 표시 값으로 바꾼다. 미래 시각·미수신·기기 재확인 상태는 ‘—’다.
- `LockWidgetSelection`: 부품 범위, 순환과 위젯 ID·공급자 일치를 검사하는 순수 모델이다.
- `LockWidgetRenderer`: 투명 바탕에 흰 원형 잔량계·자체 제작 아이콘·숫자를 그린다.
- `AirPodsLockWidgetProvider`: 칸별 선택을 저장하고 명시적·변경 불가 PendingIntent로 탭을 받는다.
- 기존 `AirPodsWidgetProvider.updateAll`에서 잠금 위젯도 갱신한다. 새 수신 루프는 만들지 않는다.

선택한 이어버드 쪽만 밝게 표시한다. 숫자 옆 작은 시계는 마지막 수신 기록이다.
접근성 설명에는 부품·잔량·수신 시각·다음 탭의 부품을 넣고 개인 기기명은 넣지 않는다.
접근성 설명 문자열 검증과 실제 TalkBack 음성 탐색은 별개다.

Samsung 확장 XML 속성 `widgetStyle=2`, `widgetSize=1`, `initialLayoutTiny`,
`monotonePreviewLayoutTiny`로 등록했다. Fold8에서 시계 아래 목록에 나타나는 것을 확인했다.
Android의 모든 런처가 이해하는 등록 방식은 아니며, 다른 One UI에서 작동한다고 보장하지 않는다.
Samsung 코드·이미지·APK는 앱이나 저장소에 포함하지 않았다.

## D18.5 의존성 순서의 태스크와 재현 방법

### 1.1.1 표시 의미부터 고정하기

UI보다 먼저 기록의 의미와 잘못된 값의 경계를 정한다. `LockWidgetTests`에서 0·100·범위 밖 값,
미수신·미래 시각·연결 해제·기기 재확인 상태를 넣어 표시 값을 비교한다.
잔량이 없을 때 선택을 바꾸더라도 ‘—’여야 한다. `./test-core.sh`로 기존 모델 검사와 함께 실행한다.

### 1.1.2 탭이 자기 위젯만 바꾸게 하기

위젯 ID와 공급자가 실제 설치된 위젯 정보와 일치할 때만 선택을 저장한다.
홈 위젯과 저장 파일을 분리한다. 명시적 broadcast의 주소에도 공급자·ID를 넣어 클릭이 섞이지 않게 한다.
잘못된 ID·다른 공급자·삭제 후 클릭을 검사하고, 위젯을 지울 때 저장값과 PendingIntent를 정리한다.

### 1.1.3 작은 공간에서 렌더링하기

48·56·64·80dp와 글꼴 배율 0.8·1·1.3·2에서 실제 Android RemoteViews를 적용해 본다.
100%와 알 수 없는 값도 넣는다. 숫자 폭과 높이를 제한해 바깥 픽셀이 잘리지 않는지 검사한다.
아이콘의 밝은 쪽이 선택 부품과 일치하는지 별도 픽셀 검사한다.

### 1.1.4 프로세스가 달라도 선택을 유지하기

격리 Android 시험에서 실제 View 클릭을 PendingIntent와 제품 수신기까지 전달한다.
위젯마다 왼쪽→오른쪽→케이스를 순환시키고 다른 잠금 위젯·홈 위젯 선택이 유지되는지 비교한다.
프로세스를 다시 시작해 선택을 복원한다. 이는 폰 재부팅 뒤 잠금화면 복원과는 다른 시험이다.

### 1.1.5 기존 설치 위에 적용하고 실제 화면 확인하기

개인 테스트 APK의 기존 서명으로 업데이트해 홈·잠금 위젯 배치가 유지되는지 확인했다.
삼성 편집기의 선택 목록과 실제 표시를 확인한 뒤 사용자가 직접 탭 전환을 확인했다.
공식 배포 APK는 별도의 기존 배포 키를 사용한다. 개인 테스트 키와 섞지 않는다.

## D18.6 검증과 남은 범위

| 검사 | 결과 | 의미 |
| --- | --- | --- |
| 핵심 배터리 모델 | 263,039개 통과 | 기존 입력 조합 회귀 검사 |
| 잠금 모델·선택 | 7,388개 통과 | 잘못된 값과 순환 경계 |
| Android 렌더 | 288사례, 189,218개 검사 통과 | 실제 RemoteViews, 크기·글꼴·아이콘 경계 |
| Android 탭 전달·분리 | 57개 통과 | 실제 클릭 전달, ID 검증, 선택 분리·삭제 정리 |
| 새 프로세스에서 복원 | 3개 통과 | 칸별 저장값 복원 |
| Fold8 실제 화면 | 목록·아이콘·잔량 표시 확인 | Android 17·One UI 9.0 한 기기 |
| 실제 탭 사용 | 사용자가 정상 동작 확인 | 자동화된 잠금 상태 로그 시험과 구분 |

자동 검사 숫자는 입력 조합의 검사 횟수이지 연결 횟수나 시험한 기기 수가 아니다.
Android 렌더·탭 검사는 별도 격리 시험 환경에서 실행했으며, 이 저장소의 `test-core.sh`는
순수 Java 검사만 실행한다. 실기기의 개인정보가 포함된 화면·로그는 공개하지 않는다.

다른 Galaxy·One UI, AOD, 밝은 배경의 대비, 재부팅 뒤 실제 잠금화면 복원과 TalkBack 음성 탐색은
아직 확인하지 않았다. 홈 1×1의 별도 미검증 항목도 이번 잠금 위젯 결과로 덮어쓰지 않는다.
