# D-013 — 직접 조절하는 에어팟 앱

> 2026-09-08 개발 당시의 기록입니다. 아래 ‘공개본 미반영’ 표시는 당시 상태를 뜻합니다.
> 이번 선별 소스에는 포함되지만 원본 기기 자료는 공개하지 않습니다.

## Why / What

개발자가 고정한 동작을 바꾸려면 APK를 다시 부탁해야 했다. 앱 안에서 값과 적용 시점을 이해하고
바꾸며 원래 기본값으로 돌아갈 수 있도록 한다. 기존 배터리 통신과 검증한 제품 그림은 유지한다.
아이콘은 이번 범위에서 제외한다. room만 수정하며 커밋·공개본 반영·배포 없이 설치까지 진행한다.

후속 요청(2026-09-08): 사용자가 앱 아이콘 제작도 요청해 별도 범위로 추가했다.
[아이콘 설계·프롬프트·검증](../../assets/icon/README.md). 최초 제외 결정을 지우지 않고 후속 요청을 구분한다.

## 근거와 판단

Apple 공식 iOS 26 AirPods 설정 이미지(https://support.apple.com/ko-kr/108764)를 직접 열어 확인한다.
상단 기기 정보, 흰 설정 그룹, 검정 본문과 회색 보조 설명, 파랑 조작을 사용한다. Samsung 권한은
없애거나 자동 허용하지 않는다. Apple 전용 ANC/공간 음향 등 지원하지 않는 기능은 그리지 않는다.
느낌의 목표는 장식보다 ‘이 값은 여기서 바꾸면 되겠구나’라는 익숙함이다.

## 시나리오 / 권장 동작 / 예상 검증

| ID | 시나리오 | 기준 |
|---|---|---|
| A1 | 업데이트 | monitor/popup/low, 기기 선택, 마지막 배터리를 보존. 새 키는 기본값만 읽는다. |
| A2 | 카드가 너무 오래 남음 | 직접 닫기(기본) 또는 자동 닫기 3–60초를 선택. 다음 카드부터 적용. |
| A3 | 배터리 경고 시점 변경 | 이어버드·케이스 각각 5–50%. 다음 수신부터 적용하고 세션 중 경고 연타는 막는다. |
| A4 | 값을 고르다 취소 | 저장하지 않으면 이전 값 유지. 숫자 범위 검증과 저장 실패 안내. |
| A5 | 기본값 복원 | 확인 후 새 조절값만 0초/20%/15%로 복원. 기기·권한·기존 ON/OFF는 유지. |
| A6 | 연결되지 않음 | 캐시와 현재 값을 구분. 미리보기는 저장값이며 연결 성공처럼 표시하지 않는다. |
| A7 | 좁은/넓은 화면 | 최대 폭·스크롤·줄바꿈 지원, 기술 진단은 접힌 상세에 배치. 권한 부족은 별도 표시. |

카드 내부의 모델·회전과 DND/잠금 안전 경계는 유지한다. 미리보기도 설정한 자동 닫기를 시험할 수
있게 한다. 신호를 받지 못하는 상태에서 경고 임계값을 바꿔도 새 값을 만들어 알림을 울리지 않는다.
30초 AAP 관측 제한·재시도·BLE 주기는 사용자 취향이 아니라 안정성 제약이므로 노출하지 않는다.

## 의존성 우선 구현과 반복 검증

범위 검증 모델 → 기존 prefs 확장 → 소비 지점(overlay/경고) → 화면 → 회귀·실기기 순서.
1차 시나리오와 기존 정책 충돌 검토, 2차 순수 경계·기본값 테스트, 3차 저장 취소·재실행·실제 카드 확인.
실제 새 AirPods 연결과 음악 무중단은 사용자가 없는 동안 임의로 착용하거나 연결을 강제해 증명할 수
없다. 이 부분은 미확인으로 남기고 저장값 미리보기와 코드 검사로 구분한다.

## 구현 중 발견과 설계 보완 — 2026-09-08

1. 경고 기준을 바꾸면서 정책 객체까지 새로 만들면 이미 알린 낮은 배터리를 다시 알릴 수 있다.
   따라서 기존 세션의 알림 이력은 유지하고 임계값만 갱신한다. 다음 수신에서 새 기준을 평가한다.
2. 값 선택창은 Activity를 일시정지하지 않는다. 뒤쪽 화면의 1.5초 주기 갱신을 창 포커스와 연결해
   선택창이 열린 동안 멈춘다. 다시 앱 화면으로 돌아오면 갱신을 재개한다.
3. 선택창 검사 실패를 처음에는 뒤쪽 갱신 문제로 의심했다. 그러나 갱신 수정 뒤에도 기기의
   `uiautomator dump`가 null root를 반환했다. 테스트 도구가 이전 XML을 읽던 것이 실제 확인됐다.
   실패한 dump는 즉시 중단하도록 고쳤다. 화면 갱신이 dump 실패의 원인이었다고 단정하지 않는다.
4. 폴드의 화면 캡처에는 실제 켜진 물리 display ID를 지정한다. 기본 screencap 출력에 다중 화면
   경고가 섞여 PNG가 열리지 않는 문제도 있었다. 최종 숫자 저장·취소·복원은 새 캡처로 직접 확인했다.

내 판단: 기기가 연결되지 않아도 설정 화면의 쓰임은 있어야 한다. 마지막 값을 현재 잔량처럼 보이게
하지 않고, 미리보기·값 조절·권한 확인은 독립해서 쓸 수 있게 하는 편이 맞다.
현재 화면의 느낌은 Apple의 정보 위계에 맞췄지만 숫자 선택창과 키보드는 Android 기본 구성이다.
iOS를 완전히 복제했다고 부르지는 않는다.
