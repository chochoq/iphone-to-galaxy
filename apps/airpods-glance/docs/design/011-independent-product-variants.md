# 011 — 신호 검증과 분리해서 진행하는 제품 자산

> **2026-09-07 실기기 iOS 관측으로 정정:** 사용자가 직접 iOS에서 케이스만 열어 확인한 결과,
> 이어버드 두 개는 각각이 아니라 **한 쌍으로 함께 회전**하고 케이스 이미지는 **닫힌 상태**다.
> 따라서 011.2의 독립 회전 목표와 011.5의 운영 앱 적용 판단은 이 시나리오에서는 폐기한다.
> 독립 자산과 검증 결과는 실패 이력으로 보존하되 앱은 검증된 기존 pair 회전으로 되돌린다.
> 새 의존성은 정확한 닫힌 케이스 자산의 형상 검증이다.

## 011.1 진행 정정

010 단계 뒤 실물 대응을 기다리며 작업 전체를 종료했다. 사용자는 부재 중에도 계속 진행하라고
했으며, 실물 신호가 없어도 가능한 자산·미리보기 작업까지 멈춘 것은 범위를 너무 좁힌 판단이었다.
센서 연결만 보류하고 로컬 시각 자산 작업은 계속한다.

## 011.2 시나리오와 설계 판단

- 둘 다 밖: 두 물체가 공통 중심 주위를 공전하지 않고 각각 자기 중심으로 회전한다.
- 하나만 밖: 단일 이어버드 자산과 반대쪽이 수납된 케이스 자산을 준비한다.
- 둘 다 안: 수납된 케이스를 준비하되 별도 이어버드 그림은 중복 노출하지 않는 것이 목표다.
- 상태 미상: 자산을 준비했다는 이유로 센서 상태를 확정하지 않는다. 운영 앱 자동 선택은 보류한다.

Apple 실제 영상의 쌍 회전 복제가 아니라 사용자가 요청한 독립 회전 UX다. 현재 승인된 Q 조명,
원본 mesh, 재질 설정을 재사용한다. 좌우 해부학적 이름을 추정하지 않고 원본 두 하위 그룹을
asset A/B로 구분한다. AAP primary/secondary와 이 A/B는 아무 관계가 없다.

## 011.3 의존성·모범 동작·검증

먼저 원본 그룹을 분리하고 회전 중심을 저장한다. 독립 회전에서는 각 그룹의 중심 이동이
없어야 한다. 다음 빈/한쪽/양쪽 케이스 가시성 목록을 만들고, 마지막에 렌더한다.
같은 케이스는 공통 카메라 중심·배율을 사용해 상태 전환 때 케이스 크기가 튀지 않게 한다.
케이스에 붙은 수납 이어버드는 케이스와 함께 회전하고 독립 회전하지 않는다.

1차 구조 검사: 각 bud의 mesh 집합 비중첩, 빈 케이스에서 stand-in 제외, 수납 변형별 mesh 차이.
2차 수치 검사: 여러 각도에서 각 bud 중심 고정과 360도 원위치, 케이스 공통 프레이밍.
3차 시각 검사: 0/90/180/270도 직접 보기. 수납 홈이 원본에 모델링되지 않았다면 숨기지 않고
결함으로 남기고 해결한다. 통과하지 않은 자산을 휴대폰 운영 화면에 넣지 않는다.

## 011.4 결과 예측

원본의 두 EMPTY 하위 그룹이 각각 완전한 이어버드라면 mesh를 자르지 않고 독립 회전이 가능하다.
기존 전체쌍/케이스 렌더 경로는 기본값으로 보존하고 --variants 옵션에서만 새 자산을 만든다.
결과와 발견은 결과 문서에 기록하며 실제 케이스 상태 자동 판별과 별도 완료 기준을 적용한다.

## 011.5 구현 중 확인과 적용 범위 정정

28 cardinal PNG에서 두 하위 그룹의 독립 회전과 네 케이스 변형을 확인했다. 정면의 낮은 카메라로
빈 케이스의 내부 홈 전체는 검증할 수 없으므로 내부 형상 검증 완료로 확대하지 않는다.
독립 pair는 물리 센서와 무관한 사용자 요청이므로 기존 카드의 animation resource만 교체한다.
케이스 자동 선택은 그대로 보류한다. 새로운 pair는 180 unique frame/6000ms/알파/클리핑/
루프 경계 수치 검사를 통과했다. 기존 pair 자산은 복구와 비교를 위해 삭제하지 않는다.
