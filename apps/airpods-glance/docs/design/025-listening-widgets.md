## 1. 목적과 시나리오

배터리를 읽는 위젯과 실제 소음을 바꾸는 위젯을 분리한다. 기존 배터리 위젯의 데이터·배치·탭 동작은 유지한다.
소음 제어 위젯은 3×1 이름/아이콘 직접 선택, 2×1 아이콘 직접 선택, 1×1 순환형과 잠금 한 칸형이다.

| 상황 | 선택한 동작 | 실패 조건 |
|---|---|---|
| 홈에서 원하는 모드를 고름 | 3×1/2×1의 목표 버튼을 누름 | 기기 응답 없이 성공 색을 먼저 표시 |
| 한 칸만 사용 | 실제 현재 모드를 확인한 뒤 사용자가 고른 순서로 전환 | 오래된 표시만 보고 다음 모드를 계산 |
| 적응형을 사용하지 않음 | 편집기에서 두 모드만 체크 | 두 개 미만 허용, 선택과 순서가 서로 다른 상태 |
| 여러 번 누름 | 진행 중 추가 입력은 쌓아 두지 않음 | 나중에 재연결한 뒤 지난 요청 실행 |
| 음악 중 UI 설정 편집 | 설정 초안만 바꾸고 저장할 때 옵션 반영 | 편집·미리보기가 Bluetooth 명령을 전송 |

## 2. 표시와 제어

`ListeningWidgetStore`의 마지막 관측과 제어 요청은 별개다. 위젯은 과거 보고를 표시할 수 있지만,
순환은 탭보다 새로운 보고를 확인한 뒤 계산한다. 현재 모드를 읽지 못하면 추측해 전환하지 않는다.
오래된 상태라는 설명은 텍스트/접근성 정보로 유지하고, 새로고침처럼 보이던 화살표·시계 배지는 제거했다.

명시적인 위젯 탭은 최대 15초의 foreground service로 처리한다. 실제 등록된 위젯 id, 종류,
명령과 URI를 대조한다. immutable PendingIntent를 사용하고 서비스는 외부 공개하지 않는다.
연결·권한·기기 변경·기한 종료 때 정리하며 부팅 작업이나 재시도 대기열을 만들지 않는다.
배터리와 기존 소음 제어가 공유하는 연결을 사용한다. 별도의 추측 명령이나 새 프로토콜은 추가하지 않았다.

## 3. 한 목록 편집기 — D-026

초기 화면은 스위치 목록과 순서 목록이 따로 있었고 앞으로/뒤로 버튼이 여섯 개였다.
실제 화면을 검토하니 큰 제목·설명·중복 목록 때문에 짧은 편집이 복잡해 보였다.
기능 통과만으로 시각적 일관성이 확보됐다고 볼 수 없었다.

Apple 계열의 그룹형 행·작은 편집 제목을 기준으로, 한 목록에서 체크 선택과 손잡이 드래그를 하도록 바꿨다.
이는 자체 Android View 구현이며 Apple 폰트·SF Symbols·원본 에셋을 반입한 것이 아니다.
관련 원칙: [Apple HIG — Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets),
[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility).

- 포함한 모드가 지정 순서대로 먼저 나오고 제외한 모드는 끝에 남는다. 재포함은 순서 끝으로 간다.
- 최소 두 모드가 필요하다. 추가 해제 시 값은 유지하고 인라인 안내를 한다.
- 손잡이만 정렬 입력을 받는다. 본문은 선택/스크롤, 헤더는 취소/저장이다.
- 드래그 중에는 위치만 미리 보여 주고, 놓을 때 초안 순서를 바꾼다. CANCEL/다중 터치는 취소한다.
- 접근성의 앞으로/뒤로 이동 액션과 키보드 방향키를 같은 초안 메서드에 연결했다.
- 화면 재생성 시 원본과 초안을 따로 복원한다. 취소는 무쓰기, 저장은 명시적으로 한 번이다.
- 다른 곳에서 옵션이 바뀌면 덮어쓰지 않는다. 일반 편집의 무변경 저장은 비활성이다.
- 런처에서 들어온 위젯 구성 요청은 기본값 그대로도 완료할 수 있다. 이 경우 새 개별 옵션을 만들지 않는다.

## 4. 의존성 순서·태스크와 발견 이력

### 1.1.1 표시와 요청을 먼저 분리한다

배터리의 부품 표시 전환을 그대로 재사용하면 실제 소음 변경이라는 의미가 사라진다.
Options/Request를 순수 Java로 만들어 두세 모드의 모든 순열과 새 관측·기한·한 번 전송을 검사했다.
Controller 수명과 표시는 이 계약에 의존하도록 한다.

### 1.1.2 서비스 진입을 실제 화면에서 확인한다

다른 UID의 테스트 위젯을 통해 foreground service 시작/종료를 확인했다.
잠겨 있을 때의 실행 거부를 홈 성공으로 바꾸어 기록하지 않았다. 화면이 열린 상태의 실행 경로와
실제 제품의 연결 없음 종료를 따로 확인했다. 실제 AirPods 전환 성공으로 대신하지 않는다.

### 1.2.1 초안을 UI보다 먼저 만든다

두 목록이 같은 배열을 중복 출력하던 Activity에서 `ListeningOrderDraft`를 분리했다.
원본/초안, 최소 두 개, 재포함, 유효한 이동, 원래 순서로 돌아왔을 때 무변경을 먼저 시험했다.
그 다음 체크 행·손잡이·Activity 저장/복원을 연결했다. 설정 파일과 키는 그대로다.

### 1.2.2 실제 드래그와 캡처에서 나온 반례를 수정한다

첫 실제 드래그 검사에서 마지막 행으로 가지 못했다. 시각 위치가 목록 끝에서 제한된 상태에서
엄격한 중심 비교를 사용하면 끝 행 중심을 넘어설 수 없었다. 경계 포함 비교와 입력 중심 기반 목표 계산으로 고쳤다.
서로 다른 행 높이에서도 끝→처음 왕복, 중간 초안 불변, CANCEL/추가 포인터 취소를 다시 시험했다.

소프트웨어 Canvas 사진에서는 자식 배경이 그룹의 둥근 모서리와 구분선을 덮었다.
그룹 자식을 명시적으로 둥근 경계 안에 그리고, 구분선은 자식 뒤에 그리도록 바꿨다.
큰 글씨에서 한국어 단어가 갈라져 안내를 줄이고 읽기 전용 문장에 단어 단위 줄바꿈을 적용했다.
문자 폭 검사와 실제 이미지 검수를 둘 다 수행했다.

### 1.2.3 위젯 구성의 무변경 완료를 보존한다

저장 비활성화를 모든 진입에 적용하면, 런처가 구성을 요청했을 때 기본값 그대로 완료할 수 없었다.
일반 편집과 런처 구성 요청을 구분했다. 구성 요청은 무변경도 완료하되 저장소에 불필요한 개별 설정을 쓰지 않는다.
이 예외는 화면 전체에 무조건 활성 저장 버튼을 두는 이유가 되지 않는다.

### 1.3.1 공개용 빌드와 개인 설치를 구분한다

새 위젯과 편집기의 의존 소스, 테스트, 개인정보 없는 UI 예시를 함께 포함한다.
기존 배포 라이선스와 자산은 유지하며 로그·개인 설정·서명 키·원본 연구 자료는 포함하지 않는다.
9월 15일 변경은 소스 커밋만 했고, 9월 16일 후속 승인으로 0.0.4 APK에 포함했다.
새 편집기는 아직 실물 Galaxy에 설치하지 않았다.

## 5. 검증 범위

UI의 네이티브 검사는 AOSP ATD Android 15 에뮬레이터에서 진행했다.
실제 제품 View를 권한 없는 별도 패키지에 넣어 320/390/600dp, 글씨 100/130/200%,
짧은/일반 높이와 두세 모드 선택을 조합했다. 실제 터치 전달·취소·저장·Activity 재생성도 검사했다.
[검사 코드와 재현 명령](../../tests/listening-widget-render/README.md)

공개용 소스로 다시 빌드해 순서 편집기 3,288개 검사·36개 화면 조합,
위젯 4,730개 검사·320개 화면, 문서용 이미지 6장 출력을 통과했다.
순수 Java의 위젯 계약 659개와 초안 계약 3,876개도 통과했다.

기존 위젯 개발본의 설치·홈 표시·연결 없음 안내는 Fold8·Android 17·One UI 9.0에서 확인했다.
새 편집기의 실제 Galaxy 모습, TalkBack 음성 탐색, 실제 위젯 소음 전환·음악 유지,
삼성 잠금 중 제어는 별도 확인이 남아 있다. 앱 안 소음 제어 버튼의 실물 시험과 혼동하지 않는다.
