# 010 — 케이스 점유 신호 검증용 관측 계층

## 010.1 목적과 판단

사용자가 없는 동안에도 진행하되 물리적인 착용·수납 상태는 만들어내지 않는다. 충전 중이라는
사실은 배터리 정보이지 항상 수납의 증거는 아니다. 특히 완충·케이스 방전이 반례다.
내 판단은 멋진 상태 전환보다 틀리지 않는 표시가 먼저라는 것이다. 현재의 조명과 움직임은
보존하고, 검증 전에는 케이스 그림을 센서 기반이라고 주장하지 않는다.

## 010.2 근거와 한계

LibrePods `docs/AAP Definitions.md`, commit `53679cc90222e94ade84e66542d97ace2540e626`:
https://github.com/kavishdevar/aln/blob/53679cc90222e94ade84e66542d97ace2540e626/docs/AAP%20Definitions.md

문서상 프레임은 `04 00 04 00 06 00 primary secondary`, 값은 00 착용, 01 귀 밖,
02 케이스 안이다. primary가 바뀔 수 있다는 주석이 있다. 이는 Apple 공식 명세도,
우리 Pro 3의 실측도 아니다. GPL 구현을 복사하지 않고 이 wire-format 설명을 근거로
독립적인 최소 판독기를 작성한다. 연결 버퍼당 한 프레임이라는 기존 transport 가정도
남아 있다. 다른 길이의 보고는 거부하고 추측해서 마지막 두 바이트를 쓰지 않는다.

## 010.3 사용자 시나리오와 모범 동작

| 시나리오 | 목표 표시 | 이번 검증 경계 |
|---|---|---|
| 둘 다 케이스 안 | 수납된 케이스, 좌우 배터리 유지 | 02/02 후보를 집계하되 그림 미변경 |
| 둘 다 꺼냄 | 빈 케이스와 독립 회전 이어버드 | 00/01 조합 후보, 좌우는 미확정 |
| 하나만 꺼냄 | 남은 한쪽만 수납된 케이스 | primary를 왼쪽으로 간주하지 않음 |
| 완충 상태로 수납 | 여전히 수납 표시 | 충전 false를 꺼냄으로 변환하지 않음 |
| 케이스 방전·보고 누락 | 상태 미확인 | 알 수 없는 값을 01로 대체하지 않음 |
| 30초 관측창 종료 | 과거값을 현재라고 표시하지 않음 | UI에 관측값 자체를 연결하지 않음 |
| 음악 재생 중 연결 | 재생 비간섭 | 기존 요청·타임아웃·연결당 한 번 불변 |

## 010.4 반복 검증과 의존성 순서

1차: 문서의 primary/secondary 주석을 확인해 좌우 고정 가설을 기각했다.
2차: 완충·방전·낯선 값·잘린 패킷을 반례로 삼아 unknown 보존을 요구했다.
3차: 합성 fixture 전수 조합/잘못된 길이/다른 opcode를 테스트한다. 이 통과는 실물 확인이 아니다.
4차(물리 실측 대기): 양쪽 수납 → 왼쪽만 꺼냄 → 둘 다 꺼냄 → 오른쪽만 수납 순서와
반대 순서를 독립 연결에서 반복하고, 완충 수납도 확인한다. 사람의 관측과 신호를 대조한다.

개발 순서: 순수 판독기 → 경계 테스트 → 기존 read loop의 진단 연결 → APK 검사.
그 뒤에야 세션/신선도 모델 → 좌우 대응 검증 → 케이스 자산 → 독립 회전 → 실기기 화면 검증이다.
수집기는 이미 수신 중인 opcode만 읽고, 새로운 요청·연결·재시도·상시 스캔을 추가하지 않는다.

## 010.5 진단과 개인정보

유효 보고 수, 미지원 길이 수, unknown 포함 수, 두 slot 코드 조합별 누적 수만 저장한다.
코드는 00/01/02/unknown으로 제한해 키 수를 유한하게 유지한다. 원본 패킷, 주소, 착용 시각,
좌우 추정, 행동 이력을 저장하지 않는다. 누적값은 현재 상태가 아니라 과거 관측이다.
이 최소 수집으로 물리 실험 전후 delta는 볼 수 있지만 전환 순서까지 증명할 수는 없다.

## 010.6 결과 예측과 출시 경계

0x0006을 받으면 진단 카운터가 증가하고 기존 배터리·카드 처리는 그대로 유지될 것으로 예상한다.
보고를 못 받으면 상태 unknown이며 실패를 가짜 수납으로 보완하지 않는다. 이번 단계는 검증
인프라이지 상태별 그림 완성이 아니다. 앱 설치와 실제 보고 수신 여부는 결과 문서에서 별도 기록한다.
