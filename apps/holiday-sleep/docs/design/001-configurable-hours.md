# D1. 사용자가 정하는 공휴일 방해 금지 시간

> 2026-09-08 개발 당시의 기록입니다. 아래 ‘공개본 미반영’ 표시는 당시 상태를 뜻합니다.
> 이번 선별 소스에는 포함되지만 원본 기기 자료는 공개하지 않습니다.

## D1.1 목적과 경계

온·오프만 있는 앱을 사용자가 시간을 관리할 수 있는 앱으로 바꾼다. 설정 대상은 기상 알람이
아니라 **평일 한국 공휴일의 방해 금지 시간**이다. 삼성 수면 모드, 잠금화면, 시계 알람,
전화 연결·마이크·Bluetooth는 변경하지 않는다. 주말은 기존 삼성 일정이 담당한다.

이번 범위는 같은 날의 시작 < 종료인 구간 하나다. 자정 넘김은 공휴일을 시작일과 기상일 중
어느 쪽으로 판정할지 새 결정이 필요하므로 자동으로 확대하지 않는다. 거절 이유를 화면에 쓴다.

## D1.2 시나리오와 권장 동작

| ID | 사용자 행동 | 기대 동작과 이유 |
|---|---|---|
| S1 | 기존 앱 업데이트 | 07:00:15–12:00, 기존 켜짐·꺼짐과 방해 금지 규칙을 보존한다. |
| S2 | 종료를 10:00으로 고른 뒤 취소 | 저장 전에는 예약과 방해 금지를 바꾸지 않는다. |
| S3 | 시작·종료를 고른 뒤 저장 | 둘을 한 번에 저장하고 두 예약을 교체한다. 현재 시각도 새 구간으로 재평가한다. |
| S4 | 같은 시각 또는 종료가 더 빠른 시각 선택 | 기존 값은 유지하고 같은 날 시작보다 늦은 종료를 요청한다. |
| S5 | 자동 연장을 끈 채 시간 저장 | 시간만 보관한다. 저장 때문에 감시가 켜지거나 예약이 생기지 않는다. |
| S6 | 공휴일 실행 중 종료를 앞으로/뒤로 변경 | 새 구간 밖이면 자체 방해 금지만 해제, 안이면 유지한다. 다른 규칙은 건드리지 않는다. |
| S7 | 변경 전 예약이 늦게 전달됨 | START/STOP 이름대로 무조건 조작하지 않고 최신 설정·현재 시각으로 판단한다. |
| S8 | 재시작·재부팅·시간대 변경 | 저장값으로 다음 일일 예약을 계산한다. 회전 중 미저장 선택값도 보존한다. |
| S9 | 알람·방해 금지 권한 부족 | 시간 저장과 실행 가능 여부를 구분해 안내한다. 앱이 정상 실행 중이라고 단정하지 않는다. |

## D1.3 의존성 중심 구조

1. `ScheduleWindow`: Android 의존성 없는 불변 시간 구간. 초 단위 저장, 시작 포함·끝 제외,
   다음 경계 시각과 평일 공휴일 판정을 한곳에서 정의한다.
2. `ScheduleSettings`: 기존 SharedPreferences 안에 시작·종료를 원자적으로 저장한다.
   키가 없으면 기존 기본값, 잘못된 쌍이면 전체 기본값으로 복구한다.
3. `Scheduler`: 저장값을 읽어 예약·현재 상태를 정한다. 변경, 수신, 재조정을 동기화해
   예전 작업이 새 시간 설정을 덮지 못하게 한다. 이미 전달된 예전 STOP도 현재 구간을 재평가한다.
4. `MainActivity`: 시간 선택은 draft에만 적용, 명시적 저장과 되돌리기 제공. 저장된 상태와
   미저장 선택을 구분한다. 시간 선택은 분 단위지만 기존 15초는 시작 시간을 다시 선택하기
   전까지 보존하고 화면에 보여준다.
5. `ZenController`: 고정된 ‘7시~정오’ 문구 대신 저장된 시간으로 설명한다.

## D1.4 판단과 사용감

내 판단: 시간을 고르는 손동작과 실제 자동화 변경을 분리해야 마음 놓고 탐색할 수 있다.
사용자가 이미 쓰는 기상 알람과 혼동하지 않도록 화면 첫 설명과 시간 영역에 방해 금지라고
명시한다. 시작 시간을 삼성 수면 종료 시각과 자동 동기화한다고 약속하지 않는다.

기존 15초 지연을 몰래 없애지 않는다. 이는 이전에 두 규칙이 동시에 바뀌는 것을 피하려던
설계의 흔적이고 빈 구간을 만들 수 있다. 사용자가 시작 시간을 직접 다시 고르면 선택한 분의
00초로 저장한다. 이 기능만으로 규칙 사이의 인계가 끊김 없다고 보장하지 않는다.

## D1.5 반복 검증과 예상 결과

- 1차, 시나리오 검토: S2/S3/S5로 저장과 실행의 구분 확인, S4로 날짜 의미의 확대 방지.
- 2차, 순수 테스트: 매초 경계·요일·공휴일·활성 여부, 기본값 복구, 다음 예약·시간대 확인.
- 3차, 통합 검토: 오래된 START/STOP 재평가, 예약 ID 유지, 동기화, UI 취소·회전 보존 확인.
- 4차, APK 빌드·서명·권한 확인. 설치/실기기 저장 시험은 사용자 확인 후 진행하며 완료와 구분한다.

설계 순서대로 UI부터 만들지 않는다. 시간 모델과 예약에 대한 의존성이 가장 크므로 이를 먼저
구현하고 테스트한 뒤 저장·UI를 붙인다. 구현 중 발견한 수정은 이 문서와 태스크에 기록한다.

## D1.6 구현 중 반영한 수정

- 저장소 commit 실패가 메모리 값을 바꿀 수 있어 이전 값으로의 되돌림을 추가했다.
- 시작·종료를 별도 getInt 호출로 읽으면 저장과 겹칠 때 다른 세대의 값을 섞을 수 있어,
  getAll 스냅샷에서 한 쌍을 읽도록 보완했다.
- 정확한 알람 권한 확인과 예약 사이의 권한 취소를 고려해 SecurityException 폴백을 추가했다.
- 자동 연장이 꺼진 상태에서는 다음 실행 시각을 표시해 예약된 것처럼 보이지 않도록 했다.
- 기존 UI가 고정 여백을 사용하므로 시스템 바와 겹치지 않게 inset 처리를 넣었다.
- 실기기 설치는 별도 확인 후 진행한다. 로컬 테스트 성공을 UI·실제 공휴일 전환 성공으로
  확대해서 표현하지 않는다.
