# 사용자 시간 설정 — 로컬 검증 결과

> 2026-09-08 개발 당시의 기록입니다. 아래 ‘공개본 미반영’ 표시는 당시 상태를 뜻합니다.
> 이번 선별 소스에는 포함되지만 원본 기기 자료는 공개하지 않습니다.

## 완료

- 기본값 07:00:15–12:00 유지, 초 단위 저장 및 분 단위 시간 선택 구현.
- 명시적 저장·선택 취소, 같은 날 시작 < 종료 검사, 회전용 draft 보존 구현.
- 저장된 시간을 두 예약과 현재 상태 재평가, 방해 금지 설명에 사용.
- 이전 예약 ID 유지, 켜짐·꺼짐 키와 기존 규칙 ID를 보존.
- 예전 START/STOP도 최신 시각·설정으로 재평가하도록 수정.

`sh test-core.sh` 결과:

- ScheduleWindow: 2,419,550 assertion 통과. 하루 각 초·일주일 요일 반복이 포함되며
  서로 다른 사용자 시나리오가 그 수만큼 있다는 뜻은 아니다.
- ScheduleSettings: 10 assertion 통과. 가짜 SharedPreferences를 사용했다.
- Scheduler: 18 assertion 통과. 실제 Scheduler와 가짜 Android 서비스·공휴일 판정을 사용했다.

`sh build.sh`로 APK를 만들고 v2/v3 서명 검증을 통과했다. 이전 로컬 APK와 서명 인증서가 같고
캘린더 읽기, 방해 금지 접근, 정확한 알람, 부팅 수신의 네 권한만 요청한다. 인터넷·마이크 등
새 권한은 없다. 컴파일 경고는 기존 Java 8 bootstrap classpath와 deprecated Android API 안내다.

## 예측과 테스트 피드백

| 예측 | 결과 | 한계 |
|---|---|---|
| 기본값으로 기존 시간 유지 | 통과 | 설치된 앱 데이터의 업그레이드 시험은 아직 하지 않음 |
| 꺼진 채 저장해도 켜지지 않음 | 대역에서 통과 | 실제 시스템 예약 확인 대기 |
| 예전 STOP이 새 시간 구간을 끄지 않음 | 대역에서 통과 | 실제 Broadcast 전달 순서 시험 대기 |
| 알람 권한 취소 경합에서 실패하지 않음 | 대역에서 통과 | One UI 절전 정책의 정확도 보장은 아님 |
| 개인 설정과 키를 보존 | 저장소 대역·서명 비교 통과 | 실기기 업데이트 확인 대기 |

## 아직 하지 않은 실기기 시험

사용자가 업데이트를 허락하면 기존 앱 삭제 없이 교체 설치한다.

1. 기존 켜짐·꺼짐과 07:00:15–12:00이 유지되는지 확인한다.
2. 종료 시간을 선택하고 시간 선택 창 취소·앱의 선택 취소가 실제 예약을 바꾸지 않는지 확인한다.
3. 사용자와 합의한 시험 시간 쌍을 저장하고, 앱 재실행 후 값과 시스템 예약 두 개를 대조한다.
4. 동일 시각·자정 넘김 거절과 가로/세로·Fold 커버/펼친 화면 배치를 확인한다.
5. 필요한 경우 자동 연장을 끈 상태의 저장을 시험하고 원래 켜짐·시간으로 돌린다.
6. 실제 공휴일 실행과 반복 발신자·별도 알람 예외는 별도 시간 전환 시험으로 확인한다.

시계 알람·삼성 모드·폰 날짜는 수정하지 않았다. 폰에 새 APK를 설치하지 않았다.
공개 저장소 갱신, 커밋·푸시·배포도 하지 않았다.
