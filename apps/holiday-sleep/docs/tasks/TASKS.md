# 시간 설정 구현 과정

> 2026-09-08 개발 당시의 기록입니다. 아래 ‘공개본 미반영’ 표시는 당시 상태를 뜻합니다.
> 이번 선별 소스에는 포함되지만 원본 기기 자료는 공개하지 않습니다.

## 1.1 시간 모델과 저장

### 1.1.1 기존 15초를 보존하는 구간 모델 — 구현·순수 검사 완료

시작을 단순히 분으로 바꾸면 업데이트만으로 15초 지연이 없어질 수 있다. 초 단위 값을 모델에
저장하고 UI의 분 선택과 분리한다. 시작 포함·종료 제외 및 잘못된 구간의 거절을 먼저 검사한다.

구현: ScheduleWindow를 UI보다 먼저 만들었다. 하루의 각 초와 일주일의 각 요일을 순회해
시작 포함·종료 제외, 평일 공휴일, 꺼짐 상태를 검사했다. 날짜가 바뀌는 다음 예약도 별도로 검사했다.

### 1.1.2 두 시간을 한 번에 저장하고 초기값을 유지 — 구현·대역 검사 완료

기존 enabled/zen_rule_id 키를 건드리지 않는다. 시간 키가 없는 기존 설치는 기본값을 사용한다.
저장 실패와 권한 부족은 다른 문제이므로 시간 저장 성공을 실행 성공이라고 안내하지 않는다.

발견: SharedPreferences.commit 실패도 메모리에는 값을 반영할 수 있다. 이전 시간 쌍을 되돌리는
처리를 추가했고, 실패를 흉내 낸 저장소로 확인했다. 실제 저장장치 고장 복구를 입증한 것은 아니다.

## 1.2 예약과 실행

### 1.2.1 모든 실행 경로가 최신 설정을 읽도록 수정 — 구현·대역 검사 완료

예전 STOP이 변경 뒤 전달되면 현재 구현은 무조건 끈다. 두 액션을 모두 현재 시각의 재평가로
바꾸고 두 경계를 재예약한다. 설정 저장과 백그라운드 재조정은 같은 락으로 직렬화한다.

구현: 기존 PendingIntent ID를 유지하면서 두 예약을 갱신했다. 실제 Scheduler 코드를 가짜
AlarmManager에 연결해 꺼진 상태의 저장, 예약 교체, 예전 STOP/START, 권한 취소 경합을 검사했다.
권한 확인 직후 정확한 알람 권한이 사라져도 부정확한 예약으로 폴백하도록 보완했다.

## 1.3 사용 화면

### 1.3.1 선택·저장·되돌리기를 구분 — 구현·컴파일 완료, 실기기 미확인

TimePicker 선택은 draft만 바꾸고 저장 버튼에서 유효성을 검사한다. 회전으로 draft가 사라지는
일과 저장 전 백그라운드 refresh가 draft를 덮는 일을 막는다. 고정 시각 설명을 모두 찾아 교체한다.

구현: 시작·종료 TimePicker, 별도 저장·선택 취소, 오류 안내, 초 단위 기존값 표시를 추가했다.
draft는 Bundle에 보존하고 상태 영역에는 저장된 시간을 따로 쓴다. 시스템 서비스 실패에도 저장
버튼이 영구 비활성화되지 않게 했다. 시스템 바 inset도 적용했지만 화면 배치는 아직 실기기에서
보지 않았으므로 UI 검증 완료로 표기하지 않는다.

## 1.4 검증과 인계

### 1.4.1 경계·예전 이벤트·빌드를 검증하고 남은 실기기 항목 명시 — 로컬 완료, 설치 대기

순수 시간 테스트, Android adapter 컴파일, APK 서명·권한을 확인한다. 공개본은 수정하지 않는다.
폰에 설치하거나 실제 방해 금지 시간을 바꾸는 시험은 이번 로컬 검증과 구분해 인계한다.

결과: 순수 모델 2,419,550개, 저장소 대역 10개, 실제 Scheduler+시스템 대역 18개 assertion 통과.
APK v2/v3 서명 확인, 이전 로컬 APK와 같은 인증서, 기존 네 권한만 유지했다. 빌드 전 APK는
private artifacts에 보존했다. 버전 미지정(코드 0)에서 코드 1·버전 1.1로 올려 새 빌드를 구분했다.
공개본 git status는 깨끗한 상태를 유지했다.

## 2.1 화면 기반과 정보 순서

### 2.1.1 색·글꼴·카드 도구부터 분리 — 완료

위젯마다 색을 넣으면 수정 때 불일치가 생긴다. UiStyle에 배경·보라색·둥근 카드·터치 피드백을
먼저 모은 뒤 MainActivity에서 사용했다. 달은 직접 그렸고 외부 이미지나 Apple 서체는 넣지 않았다.
기존 예약·시간·저장 클래스는 이번 디자인 변경에서 수정하지 않았다.

### 2.1.2 먼저 읽을 시간과 나중에 읽을 설명 분리 — 완료

첫 화면에 시간·자동 연장을 두고 상세는 접었다. 단, 권한 부족까지 숨기면 사용자가 준비된 것으로
오해할 수 있어 별도 경고로 남겼다. 저장과 취소는 draft가 저장값과 다를 때만 나타난다.
초 단위 기존 시작값을 없애지 않도록 숫자 아래 보조 설명과 접근성 설명에 남겼다.

## 2.2 화면 검증과 수정

### 2.2.1 실제 폰 설치 전에 실행 화면 확보 — 완료

기존 AVD가 누락된 시스템 이미지 때문에 실패했다. 사용자 AVD를 수리하거나 실제 폰에 설치하는
대신 임시 경로에 AOSP ATD 35를 준비했다. 공식 SHA-1과 다운로드 파일을 대조한 뒤 실행했다.
검은 캡처는 ATD의 화면 그리기 비활성화가 원인이어서 테스트 기기에서만 켰다.
권한 안내 화면을 먼저 캡처하고, 가상 기기에만 권한과 이벤트 없는 테스트 달력을 추가해 정상
화면을 캡처했다. 이 달력은 실제 삼성 공휴일 동기화가 아니다.

### 2.2.2 수정·취소·오류·저장을 화면에서 재현 — 완료

종료 12:00을 10:00으로 고르고 변경 안내와 두 버튼 출현을 확인했다. 취소 후 상세의 저장값이
12:00인 것을 확인했다. 다음으로 종료 06:00을 골라 오류 설명과 저장 비활성화를 확인했다.
다시 10:00으로 바꿔 저장한 뒤 프로세스를 재시작했다. 10:00 유지와 저장 버튼 숨김을 검사했다.

### 2.2.3 폭·글씨 크기와 기존 로직 회귀 검사 — 완료, 실기기 별도

1080×1920/420dpi, 840×1920/420dpi·글씨 1.4배, 1768×2208/420dpi 화면을 캡처해 직접 봤다.
좁은 화면에서는 시간 세로 배치, 넓은 화면에서는 중앙 폭 제한을 확인했다. 모델·저장·예약 검사
2,419,550/10/18개 assertion은 모두 통과했다. 실제 Fold 접기·펼치기와 TalkBack·회전 중 미저장
상태 보존은 다음 실기기 검사로 남긴다. 미리보기만으로 One UI 검증 완료라고 쓰지 않는다.

## 2.3 iOS 레퍼런스 재확인과 폰 설치

### 2.3.1 사용자가 거절한 색 해석을 걷어내기 — 완료

보라색 분위기는 사용자가 원한 iOS 색이 아니었다. Apple iOS 26 공식 수면 이미지에서 검정 시간과
파랑 조작을 다시 확인했다. 공통 색부터 회색·흰색·검정·파랑으로 바꾸고 큰 달과 숫자 배경을 없앴다.
그룹 간격·구분선을 조정하고 자동 연장은 초록 스위치로 그렸다. D2.6에 정정 이유와 범위를 남겼다.

### 2.3.2 설정을 유지한 개발 APK 업데이트 — 완료

사용자가 이미지 대신 폰에서 직접 보기를 요청해 실기기 설치로 진행했다. 기존 화면에서
07:00:15–12:00·자동 연장 켜짐·권한 허용을 확인했다. 1.1 백업과 새 APK의 인증서 SHA-256 일치를
확인하고 adb install -r로 업데이트했다. 기존 데이터를 지우거나 삼성 모드·알람을 재설정하지 않았다.

### 2.3.3 실기기에서만 드러난 스위치 수정 — 완료

처음에는 네이티브 Switch의 thumb/track drawable만 교체했으나 실제 One UI에서는 흰 손잡이가
잘렸다. Switch의 입력·접근성 구조는 유지하고 표시 영역 안에 직접 트랙과 손잡이를 그리도록
수정했다. 켜짐 변화에는 180ms 이동을 넣었다. 재빌드·업데이트 후 실제 화면에서 잘림이 사라진
것을 확인했다. 실제 TalkBack 전체 사용과 드래그 동작은 별도 검사로 남긴다.

## 2.4 앱 아이콘

### 2.4.1 그림 생성과 가장자리 검사 — 완료

manifest에 icon 지정이 없어 기본 이미지가 쓰이고 있었다. 수면을 나타내는 흰 달과 별을 파란 바탕에
그렸다. 첫 이미지에는 투명하고 거친 가장자리가 있어 그대로 넣지 않았다. image_gen 편집으로 배경만
교정한 뒤 불투명한 1254×1254 원본을 리소스에 복사했다. 프롬프트와 경로는 assets/icon에 남겼다.

### 2.4.2 adaptive icon 연결과 폰 확인 — 완료

API 26+ adaptive icon, API 33+ 단색 테마 아이콘을 연결하고 manifest icon/roundIcon을 지정했다.
code 4 / 1.2.2-dev를 빌드해 기존 데이터 유지 방식으로 설치했다. 실제 One UI 앱 목록에서
‘공휴일 수면 연장’의 달·별 아이콘 교체와 모서리 마스크를 확인했다. 테마 아이콘은 리소스·빌드만
확인했고 사용자의 시스템 아이콘 테마는 변경하지 않았다. 공개본 반영과 커밋·배포는 하지 않았다.
