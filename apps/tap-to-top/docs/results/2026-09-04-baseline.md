# R-001: 2026-09-04 기준선 검증 기록

## 1. 시험 환경

- 기기: Samsung Galaxy Z Fold8 (`SM-F971N`)
- Android: 17
- One UI: 9.0
- 설치 앱: `com.chocho.taptotop` 1.4.0 (versionCode 5)
- 접근성 서비스: 활성화
- 기준 구현: 일반 앱 100ms 단일 플릭, X 45ms 단일 플릭

## 2. iPhone 재확인

### 관찰

- Apple 문서에서 상태 표시줄 탭이 가까운 UIScrollView의 `scrollsToTop` 동작을
  요청한다는 구조를 확인했다.
- Apple 문서에는 고정 duration/easing 숫자가 없다.
- Safari 공개 영상 두 개의 프레임을 독립적으로 확인했다. 한 사례는 약
  0.8~0.9초, 다른 사례는 약 0.5초였고 둘 다 중간 재가속 없는 한 번의 이동이었다.

### 해석

- 복제 대상은 특정 밀리초가 아니라 `의미 기반 실제 맨 위 + 단일 연속 이동`이다.
- 사용자 가로채기는 이번 자료만으로 직접 확정하지 않는다.

## 4. X 앱 자체 기능 가설 시험

### 가설

선택된 하단 홈 탭을 다시 누르면 X가 자체적으로 피드를 맨 위로 보낼 것이다.

### 절차

1. X 홈 피드를 ADB 스와이프로 여러 화면 아래로 이동했다.
2. 화면 녹화를 시작했다.
3. 접근성 트리에서 확인한 홈 탭 중앙 `(116, 1859)`을 한 번 눌렀다.
4. 10fps contact sheet에서 전후 콘텐츠 위치를 비교했다.

### 초기 판정과 오류 발견

- 작은 contact sheet에서는 콘텐츠가 움직이지 않은 것처럼 보여 처음에 전략을
  기각했다.
- 원본 파일이 2448px 너비의 꺼진 내부 디스플레이를 기본값으로 녹화했고, 활성
  1248px 화면이 일부만 보였다는 것을 뒤늦게 확인했다.

### 수정된 결과

- 활성 물리 디스플레이 `4630947123231501204`를 명시해 다시 녹화했다.
- 홈 탭 재선택 뒤 실제 렌더링 프레임이 약 0.90초부터 1.28초까지 이어졌다.
- 약 0.38초의 단일 앱 소유 이동이며 중간 재가속은 없었다.
- 초기 `무동작` 판정을 폐기하고 X 홈 피드의 우선 전략 후보로 채택했다.

### 구현 뒤 발견한 기각 사유

- 서비스가 선택된 홈 노드를 찾고 그 중앙에 단일 탭을 보내는 시제품을 만들었다.
- 하단 바가 보이는 상태에서는 수동 시험과 같은 앱 자체 이동이 나왔다.
- 깊게 스크롤하면 X가 하단 바를 시각적으로 숨기지만 접근성 노드의 bounds와
  visible 상태는 그대로 유지했다.
- 이 상태에서 서비스가 홈 좌표를 누르자 그 아래 피드 게시물 상세 화면이 열렸다.
- 엉뚱한 콘텐츠를 여는 회귀는 허용할 수 없어 전략과 시제품을 기각했다.

## 5. Android 접근성 능력 탐지

사용자 콘텐츠를 출력하지 않는 서비스 내부 진단 경로를 만든 뒤 실제 후보를
수집했다.

| 앱 | 선택 후보 | bounds | 주요 스크롤 액션 | 절대 위치 0 후보 |
|---|---|---|---|---:|
| X | `android.view.View` | `[0,0][1248,1972]` | DOWN, FORWARD | 없음 |
| Chrome | `android.webkit.WebView` | `[0,380][1248,1748]` | UP, DOWN, PAGE UP/DOWN, FORWARD/BACKWARD | 없음 |
| YouTube | `ScrollView`, `RecyclerView` | 둘 다 `[0,0][1248,1972]` | FORWARD/BACKWARD | 없음 |
| Samsung 설정 | `androidx.recyclerview.widget.RecyclerView` | `[0,0][1248,1972]` | BACKWARD, TO_POSITION | 있음 |

### 해석

- `ACTION_SCROLL_TO_POSITION(0)`은 전 앱 공통 해법이 아니다.
- 액션을 노출한 Samsung 설정에서 반환값·종착점·프레임을 먼저 검증하고, 그 결과를
  통과한 능력 조합에만 semantic 전략을 허용해야 한다.
- X의 절대 맨 위는 현재 공개된 표준 접근성 액션만으로 해결되지 않는다.

## 6. 다음 예측

Samsung 설정에서 `ACTION_SCROLL_TO_POSITION(0)`은 true를 반환하고 실제 첫
설정 항목으로 이동했지만 즉시 점프했다. 제품 경로에서는 제외한다.

X 홈 재선택은 자동화하지 않는다. 최종 빌드는 미래 동작을 예약하지 않는 단일
플릭 기준선으로 복구한다. Chrome·YouTube에서 사용자가 가로챈 뒤 다시 올라가지
않는지와 X에서 한 번의 플릭만 발생하는지를 회귀 시험한다.

## 7. 안전 빌드 회귀 시험에서 발견한 알림창 드래그 문제

- `(300,70)`에서 아래로 시작한 드래그는 y=130까지 MOVE, y=137에서 CANCEL이
  들어왔다.
- 24dp 임계값은 이 기기에서 약 63px라 MOVE만 보는 기존 코드는 알림창을 열지
  못했다.
- 포인터가 오버레이 아래로 나가는 정상 드래그를 CANCEL로 잃은 것이 원인이다.
- CANCEL의 마지막 raw 좌표도 같은 수직 방향·거리 조건으로 판정하도록 설계를
  수정한다.
