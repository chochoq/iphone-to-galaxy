# 맨 위로 톡 설계 인덱스

## 0. 문서의 목적

이 문서는 `맨 위로 톡`의 설계 출발점이다. 결론만 남겨 과거의 실패를 다시
반복하지 않도록, 관찰한 사실·그 사실에서 내린 판단·아직 모르는 부분을
분리한다. 구현 중 가정이 틀린 것으로 확인되면 코드를 먼저 합리화하지 않고
이 인덱스와 연결 문서를 먼저 고친다.

현재 기준일은 2026-09-04이며, 기준 설치본은 1.4.0이다.

## 2. 최상위 제품 원칙

1. 상태 표시줄 탭 한 번은 스크롤 의도 한 번만 만든다. 여러 플릭을 예약해
   빠름-느림-다시 빠름이 생기게 하지 않는다.
2. 앱이 제공하는 의미 기반 네이티브 동작이 있으면 합성 손가락 동작보다
   우선한다. 이것이 iPhone의 구조에 가장 가깝다.
3. 의미 기반 동작이 없는 앱에서는 "완전한 맨 위"와 "한 번의 자연스러운
   관성"을 동시에 보장할 수 없다는 Android 한계를 숨기지 않는다.
4. 사용자가 이동 도중 화면을 만지면 사용자의 현재 의도가 자동 동작보다
   항상 우선한다.
5. 아래로 끌어 알림창을 여는 기존 상태 표시줄 습관은 보존한다.
6. 화면 텍스트·계정·사용 기록은 저장하거나 전송하지 않는다.
7. 정확한 맨 위보다 엉뚱한 항목을 누르지 않는 안전성이 우선이다.

## 3. 현재 결정 기록

| 결정 ID | 결정 | 근거 | 재검토 조건 |
|---|---|---|---|
| ADR-001 | 반복 합성 플릭을 사용하지 않는다. | 실제 참조 앱은 짧은 다중 플릭이며 사용자가 지적한 재가속과 유사했다. | Android가 단일 연속 절대 위치 애니메이션을 외부 앱에 허용할 때 |
| ADR-002 | 고정된 "iPhone 시간" 값을 만들지 않는다. | Apple이 시간·이징을 공개하지 않았고 공개 영상도 거리와 환경에 따라 달랐다. | Apple의 공식 사양이 공개될 때 |
| ADR-003 | X 홈 탭 재선택을 자동 전략으로 사용하지 않는다. | 하단 바가 실제로 보이면 네이티브 이동이 생기지만, X는 바를 숨긴 뒤에도 홈 노드를 접근성상 visible로 남긴다. 그 좌표를 누르면 아래 게시물이 열리는 치명적 오작동을 재현했다. | 실제 렌더링 가시성을 안전하게 판별하거나 X가 직접 의미 액션을 노출할 때 |
| ADR-004 | `ACTION_SCROLL_TO_POSITION(0)`은 현재 릴리스 전략에서 제외한다. | Samsung 설정에서 true와 실제 상단은 얻었지만 중간 프레임 없이 즉시 점프해 핵심 경험을 깨뜨렸다. X·Chrome·YouTube는 액션 자체가 없다. | 앱이 연속 애니메이션으로 구현한 것이 실기기 검증될 때 |

## 4. 변경 규칙

- 새 사실은 먼저 R 문서에 관찰값으로 기록한다.
- 그 사실이 기존 가정을 깨면 D 문서와 ADR을 수정한다.
- 수정된 설계에서 T 문서의 순서·완료 조건을 갱신한다.
- 그 뒤 구현하고, 예상 결과를 먼저 쓴 다음 시험한다.
- 실패를 삭제하지 않는다. `기각`, `대체`, `미확정`으로 남겨 같은 실험을
  이유 없이 반복하지 않게 한다.
