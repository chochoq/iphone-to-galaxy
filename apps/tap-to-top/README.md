# 맨 위로 톡

아이폰에서 하던 것처럼 화면 위쪽의 상태 표시줄을 누르면 보고 있던 화면이 위로 올라갑니다.
상태 표시줄을 아래로 끌면 원래대로 알림창이 열립니다.

여러 번의 스와이프를 이어 붙이지 않고 한 번만 움직입니다. 이동 중 화면을 다시 만지면 Android의
일반 스크롤처럼 멈출 수 있습니다.

X에서는 조금 더 멀리 움직이지만 아주 긴 피드의 처음까지 한 번에 닿지 않을 수 있습니다. 반복
동작을 사용하지 않는 이유는 화면이 다시 빨라지고, 사용자가 중간에 멈추려 해도 계속 움직이는
문제가 있었기 때문입니다.

왜 이 방법을 선택했는지와 실패한 방법은 [설계 인덱스](docs/design/INDEX.md)에 기록했습니다.

## 앱에서 조절하기

- 한 번 탭 또는 두 번 탭으로 실행하기
- 스크롤 세기 60–160%, 제스처 길이 40–75% 조절하기
- 접근성 권한은 유지하고 기능만 잠시 끄기
- 확인 후 조절값만 기본값으로 되돌리기

기본값은 한 번 탭·세기 100%·길이 62%입니다. 길이는 스와이프 입력의 범위이지, 목록이 실제로
움직일 거리가 아닙니다. 값을 높여도 아주 긴 피드의 처음까지 한 번에 도착한다고 보장하지 않습니다.
숫자는 저장해야 적용되며 취소하면 이전 값을 유지합니다.

설정 화면과 앱 아이콘도 함께 바꿨습니다.
[변경과 검증 결과](docs/results/2026-09-08-user-settings.md) · [아이콘 제작 기록](assets/icon/README.md)

## 확인한 환경

- Samsung Galaxy Z Fold8 (SM-F971N)
- Android 17
- One UI 9.0

다른 기기와 화면 비율, One UI에서는 터치 영역과 이동 거리가 달라질 수 있습니다.

## 접근성 권한과 개인정보

화면에서 스크롤할 수 있는 영역을 찾고 위쪽 움직임을 보내기 위해 접근성 서비스를 사용합니다.
이 권한은 다른 앱의 화면 구조를 볼 수 있으므로 소스를 검토하고 신뢰할 수 있을 때만 켜야 합니다.

인터넷, 사진, 마이크와 위치 권한은 요청하지 않습니다. 화면 내용이나 사용 기록도 저장하거나
전송하지 않습니다.

## 빌드

~~~sh
chmod +x build.sh
sh test-core.sh
./build.sh
~~~

APK는 build/tap-to-top.apk에 생성됩니다. Android SDK Platform 36, Build Tools 36.0.0과 JDK가
필요합니다. SDK가 기본 위치에 없다면 ANDROID_SDK_ROOT를 지정합니다. 직접 빌드한 APK는 개발자의
테스트용 키로 서명됩니다. 공식 APK는
[GitHub Releases](https://github.com/chochoq/iphone-to-galaxy/releases/tag/v0.1.0-preview.1)에서 받습니다.
[폰에서 설치하기](../../docs/INSTALL.md) · [배포용 서명과 업데이트](../../docs/RELEASING.md)

되돌리려면 설정의 접근성 설치 앱에서 ‘맨 위로 톡’을 끄고 앱을 삭제합니다. 권한과 앱별 한계는
[문제 문서](../../problems/tap-status-bar-to-scroll-top.md)에서 확인할 수 있습니다.
